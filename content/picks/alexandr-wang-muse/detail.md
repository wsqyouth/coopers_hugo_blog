<h2 id="摘要">摘要</h2>
<p>一两周就能做出原型，为什么还要约七个月才能发布？Alexandr Wang
回忆，Muse
最初“有时能用，而且很神奇，但大多数时候不能用，还会不断出故障”（译）。这段开发时间的核心，是让模型和产品一起变得可靠：把个人
Agent 需要的能力逐项列出来、训练、评测，直到一百多项检查不再出现“80
行绿、20 行红”，再用实际体验判断它是否真的更好。</p>
<p>用户愿意持续托付，也需要这样的连续成功。迷因和截图可以让人下载，接下来却要靠一件件做成的小事，让人愿意交出更大的任务。访谈后半程把同一问题延伸到组织：Wang
为什么放下经营九年的 Scale，怎样吸引人才重建 Meta 的 AI
实验室，以及为什么研究探索与运营改进需要不同的管理方式。他的产品故事、未来愿景与管理判断各有条件；其中既有取回遗落证件的成功轶事，也有原型失效、新人不知如何使用、创始人成为瓶颈等反例。</p>

<h2 id="origins">一、Muse 的起点，是个人生活中的一次体验转变 <span class="picks-episode-time">（00:02–08:31）</span></h2>
<p>Muse 的方向先于它的原型。Wang 回忆，2025 年 6 月，Meta Super
Intelligence Labs（MSL）成立之初，自己、Nat Friedman 等人与 Mark
Zuckerberg 讨论“个人超级智能”备忘录，想回答的是：强大的 AI
怎样改善人的生活、提升日常体验？随后团队开始搭建模型技术栈、准备数据集、进行预训练及后续训练。这套完整流程需要许多个月，愿景不能立即变成产品。</p>
<p>到了 2026 年初，Opus 4.5 让他们更清楚地看见 Agent 的潜力，OpenClaw
则把这种潜力带进个人生活。Nat 是 MSL 内很早深入使用它的人。Wang
用介于恐惧和狂喜之间形容他的体验：Nat 说想多喝水，Agent
就通过安防录像查看他有没有喝水，并给予鼓励。Wang
看重的不只是故事本身，也看重 Nat 的判断经历——很早使用
Stripe、参与开源开发者工具，并帮助打造 GitHub
Copilot。在他眼中，这位早期采用者的兴奋是一个值得认真对待的信号。</p>
<p>Wang 自己的第一次强烈体验，是使用 Nat
写的一套多轮心理探询提示。主持人追问为什么刚装好就做这件事，他的回答很直接：Nat
就在旁边，推荐他试。进一步追问体验为何强烈时，他才解释，Agent
已能访问他的邮件、照片，还能查找其他信息，再把这些信息放在一起连续追问。他感到非常脆弱，把它比作“三年的治疗压缩在一个时刻”（译）。这里描述的是一次主观感受，谈话没有给出治疗效果的证据。</p>
<p>到 2 月，两人都认为个人 Agent 值得认真建设，并各自写了备忘录。Wang
把超级 Agent 看成消费产品某种意义上的终点；Nat 的文章则影响了团队对
Agent
和信任的理解。团队用约一到两周做出原型并向董事会演示。最终产品中的小角色、早期
Charm 构想已经出现，但并非全部功能和页签都已成形。</p>
<p>Zuckerberg 也在同期亲身使用这些工具，处理家庭事务、与孩子互动，并让
Agent
看自己的综合格斗训练视频、提出改进建议。团队开会时会交流最近遇到了什么不可思议的
Agent
体验。但原型的另一面同样鲜明：偶尔很神奇，多数时候却不能正常工作，而且不断出故障。Wang
认为，OpenClaw 的热潮先升后降，也与用户反复遇到这种落差有关。</p>
<p>随后约七个月的开发，主要就在处理这道落差。Wang
想要的是一个能放心交给普通人的消费产品：长期如果要面对数十亿人，就应让其中大多数人有好体验。这是他为产品提出的标准，谈话没有证明所有任务和所有用户都已达到这个标准。</p>
<a id="二为什么选择个人-agentmeta-对自己位置的判断"></a>
<a id="二为什么选择个人-agentmeta-对自己位置的判断08311438"></a>
<h2 id="direction">二、为什么选择个人 Agent：Meta 对自己位置的判断 <span class="picks-episode-time">（08:31–14:38）</span></h2>
<p>Wang 把 Muse 的改进归于反复打磨模型与产品的结合。他先肯定 OpenClaw
创作者和贡献者的开创性，再解释团队怎样把模型路线指向个人超级智能，特别是个人
Agent。这意味着产品所需的行为要进入模型开发目标，不能等模型做完之后再考虑用户如何使用它。</p>
<p>这个方向当时并不顺着行业最强的潮流。按他的回忆，Claude、Opus
在编码上领先，资金和注意力都涌向编码 Agent，行业甚至把编码视为先进 AI
唯一重要的产品形态或能力。Meta 仍选择个人
Agent，既因为团队亲身体验过它的潜力，也因为他们相信 Meta
在这个方向有独特位置。</p>
<p>第一层理由来自他对 AI
与生活的理解。每个人都有“必须做的事”和“想做的事”；在他设想的 AGI
世界里，AI 会接过大量前者，人便能把更多时间花在后者上。他使用
Instagram、WhatsApp、Facebook，是为了追随兴趣、爱好，以及联系朋友和家人。因此，他认为
Meta 的产品已经覆盖了人愿意投入时间的生活领域。</p>
<p>第二层理由是公司传统：连接亲友、帮助人发现兴趣，本来就是 Meta
的使命。第三层才是商业分发能力——他在谈话中称，Meta 的应用每天有约 35
亿人使用。产品使命、用户动机与分发规模共同构成了他的判断，而规模本身没有证明
Meta 必然赢得消费 AI。</p>
<p>这些判断最后落成一张能力表。Wang
开头说有“数百甚至数千”项，随即自行纠正：“不是数千，而是一百多项”（译）。团队列出理想个人
Agent
所需的行为与能力，为各项建立评测，研究怎样训练模型达到要求，再在评审中找出薄弱处持续改进。这个顺序保留了产品目标如何进入模型工作的具体机制。</p>
<p>他把这与 Meta
原有的产品文化联系起来：过去逐项优化转化率、推荐率和新用户引导；到了
Muse，许多打磨发生在模型行为上。模型能否做好这些细节，直接决定产品能否兑现用途。</p>
<a id="三发布门槛评测通过还要让真实用户感到可靠"></a>
<a id="三发布门槛评测通过还要让真实用户感到可靠16562525"></a>
<h2 id="release">三、发布门槛：评测通过，还要让真实用户感到可靠 <span class="picks-episode-time">（16:56–25:25）</span></h2>
<p>一百多项能力各有两条线：低于哪条线必须阻止发布，高于哪条线才算做得好。Wang
说，团队经历过许多“80 行绿、20
行红”的检查点，知道那还不够。第一版所有项目都变绿的模型，是一个专门训练的版本，字幕记为“Musepark
1.3”，具体拼写未核实。同时，团队亲自使用后也明显感到它比此前版本好。数字过线和整体体验共同构成了发布依据。</p>
<p>这套门槛要解决的是个人 Agent 的脆弱性：模型具有非确定性，Agent
会出错。如果能稳定交付惊喜，它可能成为很好的消费产品；如果用户不断遇到不可靠的结果，也可能直接把它视为垃圾。主持人曾具体追问，有没有“九次好体验、两次坏体验就流失”这样的数据。Wang
没有给出比例，而是先把年初其他 Agent 产品的流失归因于不可靠，再解释 Muse
做了怎样的测试。</p>
<p>一类测试让新用户从下载开始使用，团队反复观察他们的完整体验。开发者早已熟悉
Agent，普通消费者却未必理解它能代人行动，与聊天机器人有什么不同，甚至不知道可以交办什么。因此，解释能力、帮助用户跨过这一步，本身就是产品工作。</p>
<p>另一类测试持续比较不同模型版本。Wang 说，A/B
测试显示体验对模型质量很敏感，敏感点包括能否可靠执行任务、能否向用户说明正在做什么，以及需要指导时能否回来询问。可靠性因而还包括沟通和求助，不能只用一次任务“完成了”来概括。主持人听完这些做法，才进一步问如何确定可以发布，Wang
随后给出了前述能力表与阈值的回答。</p>
<p>七个月的等待还需要组织上的耐心。主持人引用 Jeremy Stern 在 Colossus
的 Zuckerberg 人物特写，说 Zuckerberg
擅长建立团队、长期改善产品，又不必不断融资，可以持续做下去。Wang
先说明那篇文章太长，自己没读；他认同的是谈话里关于耐心的判断。在 AI
竞争激烈、外界不断怀疑 Meta
花钱却拿不出成果的时期，克制发布冲动需要信任开发过程。人物特写中的评价在这里仍是主持人的转述。</p>
<p>团队规模也是约束之一。按 Wang 的说法，Muse 的模型与产品工作合计不足
200
人。尽管它被视为当年极重要的产品，团队仍保持集中，因为他希望形成一套连贯体验。他批评的大组织反例是：每个产品经理都想把自己的目标塞进产品，最后出现弗兰肯斯坦式的拼装，用户会感到不同部分各有一套意图。</p>
<p>Muse 需要清晰的观点和品味。Wang 把很大一部分功劳归给 Nat
Friedman，认为他的审美和判断决定了产品的形状。主持人用乔布斯与苹果作类比；这段讨论解释的是统一体验如何形成，没有把“小团队”本身当成成功保证。</p>
<a id="四增长与传播用户关心-ai-替自己做成了什么"></a>
<a id="四增长与传播用户关心-ai-替自己做成了什么25253438"></a>
<h2 id="growth">四、增长与传播：用户关心 AI 替自己做成了什么 <span class="picks-episode-time">（25:25–34:38）</span></h2>
<p>“数百万”是 Wang
愿意披露的用户量级。他说自己转发过他人的增长图，那些图暗示 Muse
可能是增长最快的消费 AI 应用；口述时，他还把更宽泛的“消费应用”改成“消费
AI
应用”。主持人追问是否就是不愿给出具体数字，他仍只回答数百万。因此，节目提供了他对增长势头的判断，没有提供足以验证历史纪录的完整数据。</p>
<p>让人知道产品存在，与让人真正注意它，是两个问题。Wang 说，AI
模型、功能和创业公司的更新已经形成一股洪流。Meta
可以借分发能力让很多人知道
Muse，但要成为一个有趣的文化现象，还得给人意外和谈论它的理由。他也想借此让
Meta 更酷、更好玩。</p>
<p>他在 X 上的大量迷因由此进入讨论。面对“一百个 Muse
替你想帖子”的猜测，Wang
明确说每一条都是自己写的；身边确实有很懂互联网迷因的朋友。他会在会议或同事晚餐中突然想到一个点，像工程师发现
bug
的解法一样，忍不住立刻发出去。起初他主要转发用户的有趣用例，后来一些没怎么构思的帖子反而传播很好，让他重新认识到互联网会奖励风险、惊喜和出人意料的表达。</p>
<p>Nat 开玩笑说，本以为上线后会更多了解 Muse 用户，结果主要是在了解 Alex
的脑子。至于这些帖子究竟带来多少增长，Wang
的回答有明确限定：他们没有完整追踪，很难判断；他个人认为确实有贡献。主持人听说身边的人因此下载，也支持这一感觉，但两人的印象没有构成增长归因。</p>
<p>产品本身要尽早给新人一个惊喜时刻。对从未用过 Agent 的人，看到 AI
实际做成一件事，就可能刷新理解；接下来再把这些用户故事传播出去。主持人问他们是否投了广告，Wang
说做过一些，不过初期一个很直接的动作，是不断转发别人用 Muse
做出的有趣事情。</p>
<p>主持人批评的广告反例，是只展示标识、两个人坐在桌边，却没有告诉观众产品能带来什么好处。他借《Scientific
Advertising》说明，消费者关心的是自己的收益。Wang 赞同：普通人未必在意
OpenAI、其他实验室或 Meta 的研究竞赛，他们在意 AI 能替自己做什么。</p>
<p>Muse 的小角色给用例传播增加了可辨认的形象。Wang
生成过它提公文包去上班的图片，配上周一上班的意思，随后意识到这个角色能被放进许多日常场景，也能承载更大胆的笑话。角色帮助人记住产品，具体用途则让人明白为什么要试。</p>
<a id="五留存是一条逐步增加托付的路径"></a>
<a id="五留存是一条逐步增加托付的路径34383915"></a>
<h2 id="trust">五、留存是一条逐步增加托付的路径 <span class="picks-episode-time">（34:38–39:15）</span></h2>
<p>用户先给 Agent
一件小事，看到它完成，再给稍大一点的事；第二次也成功，才愿意交出更大的问题。这是
Wang
对持续使用的解释。主持人把问题从“迷因让人下载”推进到“下载以后为什么继续用”，他的回答才转向这个逐步增加信任的过程。</p>
<p>他用“向后倒下，相信有人接住”的信任练习作比喻：开始时不太相信，只是好奇，于是试一小口，再慢慢加大。他见过大学生录语音，把脑中想法一股脑倒给
AI，随后信任它整理思路、给出计划。对于真正喜欢 Muse
的用户，他强调的条件是：任务越来越大时，每一次也都要能做成。访谈没有提供这套解释对应的留存曲线。</p>
<p>主持人的亲身体验给“精心设计的新手引导”补上了一个边界：他下载应用后，并没有得到太多关于能做什么的说明，感觉更像面对一个开放的文本框。真正激起兴趣的，是朋友发来的截图。这位朋友经营一家他称为千亿美元规模的公司，把证件落在
Flexjet 飞机上，对 Muse
的要求是：“我不想参与。所有事都得由你来办”（译）。</p>
<p>按主持人的转述，Agent
安排快递取件，把证件送到办公地点，经过安保并送上楼。三四张来回对话的截图，既呈现了用户的要求，也呈现了任务如何推进。这是一则朋友通过截图分享、再由主持人讲述的成功轶事，不能据此推出所有类似任务都能顺利完成。</p>
<p>Wang
因而强调，现代消费产品还得在截图里让人看懂。截图会在群聊、口碑和公开网络中流动；小角色出现在画面里，又让人马上知道这是
Muse。他承认，其中一些传播效果并非刻意设计。与只说“它很强”相比，任务、对话与结果同时出现，让旁观者更容易理解用途。</p>
<p>他自己的使用方式则以预先配置工作流为主，把 Muse
当成第二个大脑。工作仍要求他参加会议、与人互动、保持在场，因此他并不是整天盯着应用。这个例子把持续价值放在日常任务的支撑上，而不只看用户是否不断打开聊天窗口。</p>
<a id="六第二个大脑的愿景让人的目标不断扩大"></a>
<a id="六第二个大脑的愿景让人的目标不断扩大39154524"></a>
<h2 id="agency">六、“第二个大脑”的愿景：让人的目标不断扩大 <span class="picks-episode-time">（39:15–45:24）</span></h2>
<p>Wang 相信，个人 Agent
会成为实现人的愿望与目标的桥梁。谈话先提到另一种令人担心的未来：AI
位于人之上，人只是跟着它行动。被追问自己的立场时，他明确把个人 Agent
视为一种长期形态，因为欲望、梦想和目标本来就是人性的一部分；一个目标实现后，人还会提出更大的目标。</p>
<p>他用孩子梦想拥有自己的星系作夸张例子，说明愿望未必会随着能力提高而耗尽。他也承认，人和
AI 的关系不止这一种：科学发现和经济活动的更多环节都可能越来越多由 AI
参与。个人助手是他相信会长期存在的一种关系，并不涵盖 AI 的全部未来。</p>
<p>他对 Muse
的愿景是：“让每个人拥有自己童年时梦想的成年生活”（译）。孩子会想成为宇航员、拯救地球、改变世界，进入学校和职场后，抱负却可能被不断消耗。主持人把这种感受说得更尖锐：并非自然消退，而像被生活打掉了，成年人逐渐失去能动性。这是两人对生活经验的判断，不是关于所有成年人的统计描述。</p>
<p>Wang 想让这条轨迹反过来：借助 AI
做成一件事，敢想更大的事，再去实现它。主持人回到开头那次令人不安的心理探询，提出另一种可能——如果
AI
带来的不是被剖析的脆弱感，而是更多自信，让人相信世界可以被自己的行动改变，会怎样？Wang
以杰出创业者为参照：他们实现一个愿景后，会继续追求更大的目标，有时为此工作十年。他希望这种逐步扩大行动能力的体验能属于更多人。</p>
<p>工作、家庭和其他承诺会使重新追求梦想变难，这是他认为个人 AI
有意义的现实背景。主持人随后引用 Wang
的帖文：过去塑造世界的是少数能把愿望变成现实的人，而我们还没见过每个人的能动性都充分开启的世界。Wang
想象，丰富的智能让数十亿人具备创造能力，世界会更有艺术性、更有差异，也更难预料，仿佛《瑞克和莫蒂》的跨维度电视进入现实。这些是他希望通向的未来，节目没有把它们证明为
Muse 已交付的社会结果。</p>
<a id="七离开-scale一项起初不符合熟悉逻辑的合作"></a>
<a id="七离开-scale一项起初不符合熟悉逻辑的合作45245522"></a>
<h2 id="scale">七、离开 Scale：一项起初不符合熟悉逻辑的合作 <span class="picks-episode-time">（45:24–55:22）</span></h2>
<p>Meta 与 Scale 的合作并不是从一份清晰的交易方案开始的。Wang 回忆，约在
2021 或 2022 年，经长期相识的 Meta 高管 Alex Schultz 介绍，自己开始与
Zuckerberg 接触。第一次见面从介绍到排成，印象中花了约一年。他认为这与
Zuckerberg
极强的优先级取舍有关：重要的事情要投入很多时间，家庭也需要时间，其他安排就必须让位。</p>
<p>随后两人偶尔交流创业问题。Wang 会在 WhatsApp 上提问，Zuckerberg
很快回复长而严谨的文字；他最初困惑对方哪来这么多时间，后来才发现对方写得很快。Meta
又是 Scale 的重要客户。在合作发生前，他估计双方大约半年联系一次。</p>
<p>真正改变关系的电话发生在 Llama 4 之后。Wang 解释，Llama 4 没有达到
Meta 希望的轨道，内部感到失望，同时 AI 对公司未来越来越重要。Zuckerberg
最初问的是该做什么、该关注什么，Wang 则提出许多战略想法，其中包括 Meta
在人“想做的事”上有特殊位置的判断。主持人也转述自己听说的习惯：Zuckerberg
会反复向身边有经验的创业者求建议。两人把这看作一种愿意继续学习的谦逊。</p>
<p>据 Wang
回忆，从最初联系到宣布交易，约五到六周。主持人拿另一笔交易作对比，说
Jonathan Ross 在节目里讲过，与 Nvidia 的 200
亿美元交易从首次通话到到账只用了三周。这笔金额属于主持人引述的另一个案例，并非
Scale 此次合作的价格。</p>
<p>当讨论变成“也许可以找个方式合作”时，Wang
起初甚至觉得不太合理。主持人追问原因，他先拿后来毕竟成交了打趣；主持人又把问题拉回当时，要求解释当时的判断。Wang
才给出区别：Instagram、WhatsApp 是产品逻辑清晰的 Meta 收购范例，Scale
却深耕企业和政府业务。只有 Meta
想进入那些市场，才符合他熟悉的产业逻辑；而 Zuckerberg 主要想重建 Llama
和整体 AI 计划，需要的是人才。</p>
<p>最后形成的结构，按 Wang 的说法，是 Meta 持有 Scale 的 49%，Scale
继续经营，他和少数同事加入 Meta。他认为这是一种多方受益的安排：Scale
股东获得好结果，公司也仍有未来。这个判断解释了他为何接受，不能代替每一方独立表态。</p>
<p>决定并非一通电话做成。他反复想了数周，与 Scale
同事、投资者进行了许多谈话。Scale
已经营九年，他一直将其视为人生事业；放下它意味着离开一件投入了很大部分生命的作品。促成决定的，既有交易结构，也有他在
Meta 看见的潜力。</p>
<p>Meta 当时在 AI
上的困难，反而唤起了他的创业动机：既然明显需要大量改变，就有机会从头建立原则、文化和组织。主持人称之为实验室的“重新创办”，Wang
认同。吸引他的并非接手一套成熟运转的机器，而是获得重建的空间。</p>
<a id="八从亲自做所有工作到为顶尖人才创造条件"></a>
<a id="八从亲自做所有工作到为顶尖人才创造条件5522010523"></a>
<h2 id="talent">八、从亲自做所有工作，到为顶尖人才创造条件 <span class="picks-episode-time">（55:22–01:05:23）</span></h2>
<p>小规模、扁平、技术导向和高人才密度，是 Wang
重建实验室时坚持的组织条件。他认为，AI
工作要求极快行动，这样的团队能够迅速推进；他很早就与 Zuckerberg
讨论过，并将其作为整体策略的一根支柱。</p>
<p>主持人用《The Mind of
Napoleon》中的思想作类比：行动前从各个角度充分研究，一旦决定就全力推进。Wang
表明自己没读过这本书；他对 Zuckerberg
的解释则是，对方真正接受了风险，关注的不只是失败，还包括成功时能赢多大。这种判断在他看来让
Meta 保持活力，减少走向缓慢、官僚组织的倾向。</p>
<p>Wang 对自己的管理方式也做了调整。在
Scale，他内化过一条建议：好创始人应该能做公司里的每一种工作。因此，他对每件小事怎么做都有很强的意见，公司到处体现着他的努力与判断，也使他在很多地方成为瓶颈。不过，他没有全盘否定这种方法；他仍认为，第一次创业时学会并深入各项工作，比不这样做更可能成功。</p>
<p>Meta
的任务不同：时间短、要完成的事情太多，他没有条件再亲自做所有工作。他明确承认自己不是
AI
研究员，也不是产品设计师，而这些能力又对实验室至关重要。于是，第一件事变成招来各领域最优秀的人，再让他们有条件做好工作。</p>
<p>吸引人才的理由有几层。小团队从头建立实验室，给了个人真实的塑造空间；“个人超级智能”的使命，让研究者想到自己的父母、祖辈以及普通人，愿意做能对他们有意义的
AI；Meta
的算力、基础设施和分发资源，又减少了创业公司常见的限制。资源与从头建设的机会结合，才构成他所说的吸引力。</p>
<p>主持人把高额薪酬理解为先吸引少数顶尖人才，再让他们带来更多优秀同伴，Wang
认同这一逻辑，也补充了薪酬的比较背景：OpenAI、Anthropic
的股权价值已经大幅上涨，留在那里本来就可能获得很高报酬，因此对不少人而言，换工作后的净变化未必很大。这是他的解释，节目没有提供可逐人核算的薪酬清单。</p>
<p>他把新角色比作教练：设定个人超级智能、消费 AI
和让每个人受益的方向，识别团队中的特殊才能，再给予环境和资源。大公司并不一定缺优秀人才；他认为常见问题是这些人没有被赋予做好工作的条件，于是离开去小公司或创业。</p>
<p>研究尤其需要时间、空间与试错。Wang
说，人类还不知道模型能力的极限，也没有完全理解这些系统，因此研究确实是在探索未知。Nat
的产品品味需要充分表达，研究者的想法也需要探索机会。多数想法可能失败，少数成功却可能足以证明全部投入值得。这套管理方式所依赖的，是回报高度不均的研究工作和已经具备能力的人才，而非一个“放手就会创新”的保证。</p>
<a id="九挖钻石与盖摩天楼回报形态决定工作方式"></a>
<a id="九挖钻石与盖摩天楼回报形态决定工作方式010523010912"></a>
<h2 id="payoffs">九、“挖钻石”与“盖摩天楼”：回报形态决定工作方式 <span class="picks-episode-time">（01:05:23–01:09:12）</span></h2>
<p>工作该怎样组织，要看回报怎样分布。Wang
把一类工作比作挖钻石：多数尝试可能几乎无用，少数想法却可能比其他工作有价值一百万倍。风险投资是他的例子，关键在于发现特殊机会，并支持它们一直做到结果。“一百万倍”在这里说明回报差异，并非他公布的一项研究收益统计。</p>
<p><a id="hrt"></a></p>
<p>主持人用 Wang
的十九岁生日聚会打断这个类比，开玩笑说要发现人才，只需投资当时坐在桌边的人。Wang
回忆，那是一月，自己还在 MIT 读大一，正在自营交易公司 HRT
做冬季实习。聚会约有十到十二人，多数来自 Harvard 或
MIT，很多人在数学、科学和计算机竞赛中早已认识。按他的叙述，桌边有人后来创办
Hyperliquid、Cognition、Decagon，也有人进入 Anthropic 做研究。</p>
<p>他还谈到 HRT 本身的表现：2026 年第二季度约有 110 亿美元收入、约 80
亿美元利润，员工不到一千人。这些是他在访谈中的口述数字，没有本次独立核实的财报支撑。最近遇到
HRT
创始人、听说公司开始做私人投资时，他便建议给所有实习生种子投资。这是一句以优秀同伴经历为背景的玩笑，不能据此推出普遍投资规则。</p>
<p>插话之后，讨论回到另一类工作：盖摩天楼。Wang 把数据标注、数据业务和
Amazon Prime
配送放在这一类，认为其回报更接近线性。这里要建立极好的流程，再一点点提高效率：某处提高
2%，另一处提高 1%，再一处提高 0.5%。这些数字是说明累积改进的例子，不是
Scale 已报告的效率提升。</p>
<p>挖钻石则需要允许人尝试大胆想法，再培育看起来有希望的方向。Wang
说，自己在 Meta 更像做这件事，在 Scale
则更像盖摩天楼。这个区分并没有取消前文 Muse
对可靠交付的要求：访谈同时涉及探索新能力与打磨已找到的能力，两类工作面对的回报和不确定性不同。</p>

<a id="十两百多名直属减少管理层不取消技术领导"></a>
<a id="十两百多名直属减少管理层不取消技术领导010912011215"></a>
<h2 id="organization">十、两百多名直属：减少管理层，不取消技术领导 <span class="picks-episode-time">（01:09:12–01:12:15）</span></h2>
<p>主持人猜 Wang
有一百名直属，他纠正为两百多。这个数字解释的是实验室汇报方式，与前面参与
Muse 模型和产品开发不足 200 人的口径不同。Wang 说，名为 TBD
的研究组里，招来的研究人员基本直接向他汇报；组织原则是高人才密度、技术导向，以及尽可能扁平。</p>
<p>减少人员管理层的前提，是这些研究者已经在职业经历中证明过自己能做出优秀工作。Wang
认为他们不需要被微观管理，但技术领导仍然存在：各个 pod
小组有技术负责人，负责明确方向，并在技术决策出现分歧时裁决。团队也做大量集体讨论，因为成员都有值得听取的判断，应该让这些判断进入决策。</p>
<p>他没有把非常规结构描述成完美管理。相反，他承认：“如果说我是这两百多人的最佳经理，那就是在说谎”（译）。他想提供的是一个好环境，让有能力的人获得施展空间。主持人因此把前面的“教练”改述为“好环境的守护者”，Wang
表示认同：这些人已经有能力做好工作，组织要给他们发挥的余地。</p><h2 id="插播与节目收尾">插播与节目收尾</h2><p><strong>约14:20–16:50、约35:55–37:10，以及01:11:45之后</strong></p><p>材料包含 Ramp、全球招聘与用工平台，以及 AppLovin 的广告。广告分别宣称使用 Ramp 的中位企业费用下降5%、收入增长16%，全球用工平台获四万多家公司使用，以及移动游戏广告可触达十亿多潜在客户、全屏视频平均观看35秒等。这些数字属于赞助宣传，不构成 Muse 产品或 Wang 管理方法的证据；字幕中的品牌拼写和网址也不宜直接当作校验过的信息。</p><p>最后的订阅、评论与 Founders 播客推广属于节目收尾。主持人自述近十年阅读过四百多本创业者传记，寻找可用于工作的思想。这些片段保留了材料的完整结构，但与访谈的核心论证分开理解。</p><h2 id="出处与回听">出处与回听</h2><ul><li><a href="https://www.youtube.com/watch?v=S6l3aRsecuE">Building Muse, Working with Mark Zuckerberg &amp; The Future of AI | Alexandr Wang, Meta</a></li></ul>
