## 摘要

余一与主 Agent 跑通微博抓取后，让它把代码和经验转交给负责监控的 Bot。以前她用工具跑任务，经常得隔一会儿去看。现在她只要向主 Agent 交代，后台就能继续分派、调工具和检查结果。可讲到自己的出镜视频时，她却愿意亲手做第一步。先自己讲一遍，让 AI 整理，再自己讲成稿。两件事都关乎她在流程里想留下什么。

任鑫和徐文浩从她离开腾讯研究院问起，聊到 Manus 怎么接住反馈、物业经营者怎么先做出巡店系统，也聊了简化旧 harness、挑选实习生和做社区。约时间仍会找人确认，低容错任务仍要审核，新入职看到的快也有它的语境。顺着这些例子读，可以看见自动化在哪一步省掉了来回，以及哪一步恰好是人想参与的地方。

## 为什么想换一种做事方式

### 一个人能做更多之后，她为什么还想找团队 {#from-observer}

**00:45–05:59**

在主持人看来，余一在腾讯研究院有熟悉的环境、不小的空间，也有人认可她。余一的回答回到了两年前。那时她转入研究院，如今又决定离开，两次都因为她越来越难以忍受自己只能在旁边看。

这一次，她已经试过用 AI 把一个人的能力向外扩。活确实多做了，但每个环节都自己盯会累，能做也不意味着每件都做好。她更想知道，几个人各有擅长的事、也各自和 Agent 一起工作时，怎么交接，怎么把东西一起做出来。近期试用 Bot 协作工具，让她感到这套原先需要懂 CLI、Skill 和项目管理的东西，有机会变成普通人也能理解的交互。她希望在值得信任的团队里参与这个过程。

### 微博抓取跑通了，谁去把下一步交代清楚 {#delegate-outcome}

**05:59–11:16**

余一和自己的主 Agent 跑通了微博抓取，下一步要给另一个 Bot 接手监控。她把交接也委托给主 Agent，由它拿着已有的经验和代码，让监控 Bot 跑起来。她只在原来的窗口交代一次。

她用「90%」和「100%」描述的，就是自己还要不要为最后这段来回耗着。她以前用 Claude Code 和 Codex，经常得隔一会儿去看。后来这些工具接在后台，由主 Agent 根据任务调用本地 CLI 和 Skill。她说的是反复交代、检查进展和切换窗口的负担。

### 封面能自动审核，为什么剪辑还要自己盯 {#keep-a-review-gate}

**11:16–15:18**

主持人马上拿自己做播客的流程来试这个说法。封面以前会画错人脸，他让 Claude Code 调 Codex 生图、检查人脸，发现问题就退回重做。这一关可以自动跑。成片的剪辑却交不出去，调了八个多小时，还是会出错，他仍然得参与。即使封面通过了「人脸对得上」，好不好看也得另说。

余一答的是另一类活。有些探索本来不会做，AI 能先帮一点就已经有收益。如果四个版本都在可接受范围，她会考虑先让真实用户给反馈，少花时间猜那一点差别。碰上容错率低的事，她会让独立的审核 Bot 按标准检查，过了才交给主 Agent。是否继续打磨，取决于错误的后果和这一关要判断什么。

## 到一个能接住反馈的团队

### 先把巡店系统做出来，再谈成本 {#build-before-cost}

**15:18–25:27**

余一很早就用 Manus 团队做的产品，提过需求，也报过不少问题。选择这家公司，她看中彼此信任、做事方向重合，以及用户看到的问题能有人继续做。她把自己的工作概括为产品和社区，要把重度用户遇到的问题带回能动手的团队。

节目里有位做物业管理出身的经营者，没有计算机背景，先用 Manus 接上现有设备和门店流程，做出真的有人用的巡店系统。余一问做这些要花多少钱，对方在意的是以前连这事能不能做都不知道。试通后再打磨，请 IT 把一些想法接到内部报修和看板里，才有条件继续比较成本。

余一自己的顺序也类似。未知任务先跑出一个能判断的版本，走不通就尽快放下。方向明确后，可以继续用原工具，也可以交给 Claude Code、Codex 或便宜模型。原型这一步的价值是缩短犹豫，后面才轮到工程和成本的取舍。

### 一条反馈如何找到人和上下文 {#team-context}

**25:27–38:59**

余一记得，有一次她提了个产品需求，二十分钟后就有人叫她去测，看看是不是想要的东西。她也见过做了一半的任务被取消，大家停下来换方向。这些具体经历解释了她为什么喜欢团队的节奏，二十分钟只是其中一次。

更能解释节奏的，是一条反馈经过哪些环节。她说，反馈进入 Slack 后，AI 能定级、找到该处理的人，并从 Notion 拉出以往提过几次、是谁提的、当时发生了什么。她刚来时会向内部机器人打听近期会议、产品进展和该找谁。能调取这些资料，才省下新人反复问路和团队重新讲背景的时间。

主持人追问，团队里会不会变成每个人都往群里放一个 Agent，沟通对象越加越多。余一查了查，给出的印象是，长期在用的主要是几个围绕服务建的共享机器人，比如产品通用和反馈机器人。她在描述刚入职时看到的做法。个人按信息源配几个 Bot，和公司维护共享入口，是两层不同的分工。

## 把执行交出去，重新看自己做什么

### 从海外值机到约面试，能交出去的是什么 {#agent-at-work}

**38:59–54:08**

对谈谈起用户第一次觉得 Agent 真管用的时刻。余一最近聊过五个人，其中三人说起值机。Agent 能在不熟的海外航空公司网站填资料、选座，最后把登机牌交给人。主持人随即追问，身份资料和座位偏好是不是得先给全。她认可这个前提。三个人的经历解释了为什么这类流程让他们有感。

她自己更熟的是面试日程。她让 Agent 找邮件和简历、对日历、和候选人约时间。定下来后，Agent 仍向她确认一次，然后才发邀请、占用日历、建会议链接。换账号那半天，这些琐碎又回到她手里，她才看清确认前后各有多少事情已经可以交出去了。

她也从这种经历反推 Agent 需要什么。要把它当能接手一段工作的协作者，它得有自己的运行环境、通信渠道和知识库，也得能调用其他资源。她把不同资料和任务放在几台云电脑上，也可以把明确的重活调回本地。在她的监控流程里，分开的 Bot 处理邮件、X 或融资信息，主 Agent 挑出值得深挖的线索，再派研究 Bot 调本地 Codex 的 research Skill。她关心的是工作接得起来、卡住能继续查，自己可以少来回搬材料。

### 主 Agent 怎么管后台，怎样向人交代结果 {#chief-of-staff}

**54:08–58:03**

Slack、Notion、X 和邮箱都能发来信息。余一让各自负责监控的 Agent 汇到一个群，但那个群主要给「AI 余一」看。她只对主 Agent 说话，还会特地测试它会不会分派。新任务可以先试出做法，形成套路后，就该交给能稳定接手的执行者。

对她来说，主 Agent 还得知道什么值得汇报。有些工具会把调用、报错和临时进度整段转给人，用户最后还是得自己搞清做到了哪一步。她在参与打磨 Q 时，会找具体的好坏案例，去看结果怎样说，人才能知道事情是否完成、哪里还需要自己决定。约面试的那个确认点，和后台每一次开网页、查日历，值得用不同方式交代。

### 把旧 harness 移开，看看还需要哪些规则 {#retest-the-harness}

**58:03–01:00:48**

余一有一次用 Manus 2.0 做视频，简短说明就出了满意的结果。再让模型套她原来攒的 Skill，反而多了些麻烦。她开始怀疑，过去为了解决模型弱点加进去的步骤，有些已经没在解决今天的问题。

她打算把原有 harness 和上下文移到另一个目录，让新模型在较轻的配置下重跑旧任务。她已经让 AI 审核哪些规则值得留，当时还没看结果，完整重跑也没做完。同一任务换一套约束，再看质量和验收有没有变，是她打算用来挑规则的办法。

### 谁来决定什么叫好，谁来讲第一遍 {#define-and-judge}

**01:00:48–01:10:07**

主持人问，事情都交出去以后，时间去了哪里。余一最近忙着和不同的人聊，接触用户、同事和他们的实际问题。任鑫由此推想，人也许会把越来越多时间花在给 AI 补上下文、对齐目标上。余一接下来讲的是她真做过的一次修改。

她以前让 AI 给演讲加特效，试过不少做法，结果总不太对。后来她只要求效果得跟着讲解内容和情绪走，模型就能自己选择怎样做出悬念、哪里需要强调。她也会请其他模型评估，自己参与判断。她花时间打磨的是一句能帮助验收的话。

有些判断也得经过自己。以前 AI 写好脚本，她照念就能出片。现在只要本人出镜，她要求第一遍先对着 AI 讲出来，再由 AI 整理，最后自己重讲。哪怕慢一点，这个过程也得让她想明白了什么。如果找不到那句抓住任务本质的话，她和 Agent 就会遇到新的瓶颈。别的活则可以找擅长的人做，或请人把方法教给自己的 Agent。对谈把这叫作从只靠 know-how，转向也知道该找谁。

## 怎么找到一起建造的人

### 招实习生，给一笔积分试着做点东西 {#show-your-work}

**01:10:07–01:16:54**

徐文浩问，招年轻人，和多买一个模型订阅，差别在哪里？余一回忆，过去她常替实习生找事情做。这次她希望新人能带着想法来，自己发现值得解决的问题，遇到限制也会试着绕过去。

她这轮仍收简历，但先翻视频、游戏、小工具等作品，再追问跟 AI 一起怎么做的、哪一步卡住、为什么这样选。有些候选人还会拿到一笔 Manus 积分，花一两天把想做的东西先做一点出来。她说自己已见到令人意外的作品。她也会聊工具用量，但访谈里让她印象深的，是候选人能讲清实际取舍，发现审美有短板后还主动去补。这里讲的是余一这轮怎么判断人，公司的招聘政策有多大范围适用，节目没有展开。

### 把用户观察带回能动手的产品团队 {#user-to-product}

**01:16:54–01:22:32**

谈到社区，余一还在摸底。她去找愿意付费、真的用 Manus 做项目或挣到钱的人聊，想知道哪里让他们觉得有用，哪里用不下去。她自己是重度用户，也只有一个人的观察。她希望用户愿意拿出作品和小技巧互相交流，也希望团队分享内部怎样用 AI。

节目最后，她说起入职为什么开心。遇到产品或技术问题，背后有人能接手。朋友拿别的产品来跟她吐槽，她也能挑出有意思的地方，带给自己的产品团队。开头的「不想做旁观者」到这里有了下文。她的观察终于有了去处，社区能不能带来持续的反馈，还得接着探索。
