<h2 id="摘要">摘要</h2>
<p>一条模型曲线没有继续上升，究竟是规律失效、数据条件不够，还是实验里藏着
bug？姚顺宇判断预训练仍有空间，依据是自己见到的模型越来越容易学会新东西，也依据研究者能否设计实验，逐个排除异常的原因。编程模型的快速进步提供了另一个例子：测试给出相对清楚的反馈，GitHub
提供大量可构造任务的代码，专业用户又对好代码有较多共识。但分数上涨、代码生成得更多，都还不能替人回答该解决什么问题、结果是否真正有用。</p>
<p>这套判断也贯穿他从理论物理转入 AI
的经历。本科时，周期边界下的手算与开放边界下的数值结果对不上，促成了非厄米系统描述方法的更新；博士阶段，实验难以裁决理论，又让他重新考虑什么研究值得投入。进入模型公司后，他把同样的要求放到训练稳定性、算法成本和团队协作上。访谈后半程的两个押注——让
AI
跑完研究循环、让有限上下文支持长期工作——因而既有具体机制，也有未解决的条件。以下判断以对话明确说出的
<strong>2026
年第一季度</strong>为时点，“今年”“未来六到十二个月”均从这里算起。</p>

<a id="一不是能力已经一样而是想教什么变得更难"></a>
<a id="模型差异还在难点转向定义下一件事000142001141"></a>
<h2 id="model-differences">模型差异还在，难点转向定义下一件事 <span class="picks-episode-time">（00:01:42–00:11:41）</span></h2>
<p>前沿实验室相对不再担心能否追上别人的推理能力，更担心接下来值得做什么、目标能否定义清楚。这是姚顺宇对自己接触范围的观察。他不太接受“上下半场”这种尚未说明标准的分期，也没有因此宣布模型已经同质化。</p>
<p>主持人追问：不担心追不上，是否意味着能力被拉平？他把纸面分数与使用体验分开。编程基准上，大家可能都在约
80%
附近，差一两个百分点，他认为其中可能主要是噪声；实际使用却仍有差别。在他当时的体验中，Claude
的通用工具使用和 Agent 表现突出，Codex 在纯编程上缩小差距，Gemini
在纯推理和部分日常用途上较好，编程与 Agent
仍在追近。这是一幅带有使用范围的快照。</p>
<p>差别有时来自团队选择。优先做工具、编程或推理，就会花更多时间建设相应基础设施和数据。但目标行为还说不清时，结果也可能来自意外因素：早期直接从网上取训练数据，GitHub
代码的质量可能天然高于普通网页，模型便可能先在代码上显出优势。不能看到一个强项，就倒推出团队早已精确规划了全部路径。</p>
<p>他的判断来自一条转行路径：清华物理本科，斯坦福高能理论、量子信息及黑洞相关博士研究，短暂的伯克利博士后，约一年
Anthropic 工作，再加入
Gemini。他与另一位清华计算机出身、后来去普林斯顿的近同名研究者相识多年，常从对方对人机交互和产品的思考中学习。自己这次换工作的优先项，是学不同的东西，而非先争取领导一个项目。</p>
<a id="agent-走红之后产品壁垒仍待证明001141002407"></a>
<a id="二一个-agent-产品走红证明了什么又没有证明什么"></a>
<h2 id="agent-products">Agent 走红之后，产品壁垒仍待证明 <span class="picks-episode-time">（00:11:41–00:24:07）</span></h2>
<p>一个产品把已有能力变成大众能感知的用途，也能产生重要价值。谈到字幕称作“open
cloud”的产品，姚顺宇说业内的惊讶似乎没有业外那么强：在他的印象里，公司内部已经有人做过类似实验和演示，只是尚未打磨、发布。他认为较早的强模型已经具备相关工具能力，产品展示的是协调不同模型、完成多种任务、汇总结果并持续工作的可能性。技术准备好、产品发布、产品走红，是三个不同节点。</p>
<p>但从 Manus
到这类产品究竟发生了什么质变，他承认没想明白，也不知道为什么 Manus
不能做类似事情。对访谈提及的收购，他没有给出完整行业解释。Meta
获得亚洲团队，可能多了一个吸引中国、新加坡和东亚人才的锚点；产品本身为何必须通过收购取得，他仍不理解。</p>
<p>外部小团队先做出来，也不能直接证明大公司看不见机会。一个能操作电脑的
Agent
可能拿到过多权限、损坏系统。大公司要处理法律、品牌、用户体验，并提供相对稳定的服务资源，很难发布后告诉每个用户再买一台电脑隔离运行。个人开源项目则可以先拿出来，邀请别人共同改代码。这是发布责任的差别。</p>
<p>应用能否长期独立，仍取决于壁垒。在他看来，当时许多壁垒在模型侧，尚未看到哪个应用真正形成了常被谈论的数据飞轮。聊天机器人的主要需求仍像搜索的延伸：有问题、找答案，但可以追问，也能把多来源信息浓缩成回答。编程则是他认为较明确、已经成功的
AI 原生场景。</p>
<p>他能想象两条应用路径。其一是增长足够快，先占据用户心智，再趁模型公司追赶产品形态时自研模型。Cursor
从 Anthropic 的合作伙伴，走到面对 Claude Code 的竞争、训练自己的
Composer，就是他眼中的尝试。编程效率工具服务专业需求，可能出现赢家通吃，因此高速增长也不保证安全。其二是先做足够小的市场，小到模型公司暂时不愿投入，他以
Midjourney 为例。</p>
<p>“万分之一”与“1%”是他形容赌大市场和先做小市场时使用的概率比喻，没有统计依据。若自己创业，他想做大事，却会先找一个有进一步想象空间的小切口。</p>
<a id="长期助手的预测能实现还要比较哪条路更有效002320002539"></a>
<h2 id="finite-context">长期助手的预测：能实现，还要比较哪条路更有效 <span class="picks-episode-time">（00:23:20–00:25:39）</span></h2>
<p>“Train with finite context，Use as infinite
context”是姚顺宇反复使用的目标表述：用有限上下文训练，让模型在使用时能做很长、近乎无限延续的工作。这里的助手会持续与用户交互、获得信息，再根据当前场景丢掉不重要的内容；目标并非把全部历史永久原样塞进一次输入。</p>
<p>他在这里强烈预测，2026
年内技术上会实现这一方向。支撑这份信心的，是研究者已经有多种可尝试的路线，而非完全没有想法。不过，多条路线都能跑通，也不意味着知道哪条最好：仍须在用户常见场景里比较效率。后文的<a href="detail.md#long-horizon">长期工作机制</a>进一步说明了稀疏
attention、文件存取和上下文管理各自想解决什么。</p>
<a id="三预训练没有到头的依据是排查方法不是一条口号"></a>
<a id="预训练是否撞墙先排查三类原因002453003104"></a>
<h2 id="pretraining">预训练是否撞墙，先排查三类原因 <span class="picks-episode-time">（00:24:53–00:31:04）</span></h2>
<p>模型进步完全没有变慢，是他的第一回答；被追问速度曲线时，他又明确说，必须先给出衡量标准。一个最高为
100%
的基准，越接近上限，每月能涨的点数自然越少。用户体验却不与分数线性对应：50%
到 60% 的收益可能小于 70% 到 75%；主持人据此推想 80% 到 90%
会更明显，他马上补充，也可能没有区别，甚至变差。</p>
<p>他的主要依据是研究体验：过去教模型做一件事，需要许多技巧；现在模型更容易学会，关键更常落在把问题定义清楚、准备合适的数据上。“数据”包括交互环境，不只是一批静态文本。他认为此前数月预训练仍在增强，在自己可见的未来四个月内也没看到到头的迹象。这不等于一条统一测量的行业增速曲线。</p>
<p>当有人报告撞墙，他会分开三种解释：经验规律超出了适用范围；规律成立所需的条件不再满足，例如没有足够数据；实验设计或实现有
bug。他不排除前两种，只是据自己的见闻，第三类可能很多。</p>
<p>bug 也不只有程序报错。不同尺寸模型应训练多少数据，token horizon
怎样选，数据从哪里取，这些科学假设与配置可能没有对齐；也可能真有一个实现错误尚未发现。他见过修好
bug 带来的收益超过精巧技巧。要判断规律是否失效，就不能跳过这些排查。</p>
<p>主持人提出另一种解释：觉得问题能修，就相信没到头；觉得不能修，就宣布到头。姚顺宇承认有信念成分，但把重点拉回“做事系统”：某个尺度的行为与预测不符时，列出可能原因，设计能区分它们的实验，检查怀疑的因素是否真是原因。乐观要靠这项工作支撑。</p>
<a id="四为什么此时数据与算力重要而算法仍可能带来跳变"></a>
<a id="数据算力与算法的作用取决于处在哪个阶段003104003455"></a>
<h2 id="compute-data">数据、算力与算法的作用，取决于处在哪个阶段 <span class="picks-episode-time">（00:31:04–00:34:55）</span></h2>
<p>数据与算力无法简单排先后：算力更多，往往需要更多数据；数据更多，也要更多算力才能使用。算法则可能在不同阶段发挥不同作用。尚不知道怎样扩大规模时，一次发现能让原本做不了的事变成可做；路线跑通后，许多改进主要提高计算效率和数据利用效率。</p>
<p>他用 Transformer
对语言模型预训练的作用说明前一种跳变。在已比较清楚的预训练、监督学习后训练和强化学习后训练框架内，他认为当时数据和算力是主要驱动力；多模态生成等范式未固定的方向，算法仍可能是关键。自然语言当前路线的科学框架较清楚，不代表工程已经完成，更不能推广成所有
AI 方向都只剩工程。</p>
<p>还能进步多久，他没有给出远期保证：“当你没有撞到头的时候，你其实不知道这个路有多长。”他重复可见的四个月窗口，并把研究者的兴奋限定在自己接触到的模型团队。后文<a href="detail.md#post-training">后训练扩规模</a>还会谈到，他自己也曾相信预训练的空间快用完了，后来改变了判断。</p>
<a id="五编程为什么跑得快可测试能构造环境用户标准较收敛"></a>
<a id="编程进步快因为反馈环境和用户标准同时具备003455004634"></a>
<h2 id="coding-feedback">编程进步快，因为反馈、环境和用户标准同时具备 <span class="picks-episode-time">（00:34:55–00:46:34）</span></h2><p>编程有一部分结果可验证。代码能不能运行、测试过不过，能给训练提供明确反馈。用例本身的覆盖和用户实际在意的结果，仍然需要人判断。</p>
<p>编程的优势有三层。第一，许多功能可以写成明确的输入输出要求，测试因此提供相对清楚的奖励信号。第二，GitHub
积累了多年优秀程序员的代码，能据此构造大量任务和环境。清晰反馈与足够环境必须同时存在。第三，优秀程序员对简洁、结构、合理抽象和未来维护有较多共识；与社交、游戏中差异很大的个人品味相比，编程产品更容易界定目标。</p>
<p>这条线并非刚刚开始加速。他回忆，Claude 3.5
后续版本之后就一直进展很快。自己按代码行数估计，保守说超过 90%
来自模型，不保守可以到 99%
或近乎全部。被追问剩余部分是不是模型不会写，他笑称 90%
是给自己留点面子：自己能做、模型不能做的部分正在变少。</p>
<p>但他仍需花时间检查代码是否合适、是否真的实现原意。人的工作转到设计逻辑、说明文件关联、交代背景、给出参考。早期模型容易只盯一个文件，找不到深层定义或跨文件关系；他感觉这些缺陷正在减少。测试信号有价值，并没有取消对抽象和维护性的判断。</p>
<p>从实现想法、做实验的个人效率看，他估计比一年或一年半前提高了 20–50
倍：可以并行开几个模型试不同想法，有时还让它们监控实验和结果。这不是对所有程序员产能的测量。效率提高甚至让他的工作时间更长、密度更高：过去遇到陌生文件，可能要等几小时找人解释；如今模型五秒钟讲明白，就能继续。等待消失，想试的东西又越来越多。</p>
<p>基础科学已经受到类似影响。一个不擅编程的研究者，过去可能半天才把程序和环境跑起来，现在几分钟就能开始试想法；模型也在辅助数学推导、证明和论文归纳。这些影响不一定形成巨大市场，也尚不能据此说
AI 已作出爱因斯坦理论级的发现。</p>
<p>人类觉得智力上最难的数学和编程，为什么反而更适合模型？他的答案仍是评价标准：一旦知道怎样判断结果，就知道怎样提供训练反馈。好的产品经理则常要把东西做出来、交给人使用，才知道究竟好不好；他当时还想不清楚如何为这种判断提供同样明确的训练信号。</p>

AI，他倾向肯定，但承认并不知道内部情况，关于其外在表现的解释只是猜测。</p>
<p>这段还出现了一个技术领导的例子。姚顺宇没有与吴永辉直接共事，主要通过旧代码和项目看到其技术能力，认为层级很高仍保持这种能力很难得；这一观察不等于完整的人物评价。</p>

<h2 id="robotics">机器人跨过门槛，要看一处训练能否带来普遍提升 <span class="picks-episode-time">（01:03:42–01:09:13）</span></h2>

<a id="九选择难事的成长史也包含难不等于值得的教训"></a>
<a id="从争取一次考试开始学习依靠具体行动010825012218"></a>
<h2 id="learning-path">从争取一次考试开始，学习依靠具体行动 <span class="picks-episode-time">（01:08:25–01:22:18）</span></h2>
<p>拿到清华录取机会的关键动作，是在夏令营最后一天发短信争取参加一场考试。姚顺宇听说当时的自主招生主要面向北京学生，就要求让一起参加夏令营的上海同学也能竞争。短信原文、人数和许多细节他已经记不清，也不确定别校是否有人同时争取；最后他们获准参加，他拿到了降至一本线的录取条件。</p>
<p>这不是物理竞赛保送。他进入过省队，却没有进到能获得保送资格的国家集训队；高考也没有达到清华常规录取分数。经历留给他的认识是：“争取了也有可能得不到，但不争取就绝对得不到。”他当时主要想着机会就在当天，得赶快行动。</p>
<p>更早的选择也并非一路顺遂的天才模板。他出生在宁夏煤矿城市，小学阶段随父母到上海，初中不是竞赛强校。选择格致的竞赛机会，是因为没做过、觉得有挑战，想体验一次。主持人把这概括成放弃四校普通班，他纠正：做决定时还没中考，能上四校并非板上钉钉，虽然后来的分数确实够了。</p>
<p>父母较少干涉，让他能对认定的事情负责。他的好胜更多指向自己：想做就尽力做好，不想做则很难靠外力逼出投入。本科基科班鼓励早进科研，也不要求学生最终都做物理；他想做理论，便去高等研究院找老师，跟王忠读论文、讨论，逐渐进入凝聚态、拓扑绝缘体方向。</p>
<p>这个方向适合本科生，在他看来不是因为简单，而是基础知识范围比较明确：量子力学、统计力学、固体物理等入门后，就有机会做具体项目，难点转到理解是否足够深。读材料、讨论问题、动手检验，构成了他后来偏爱的学习方式。</p>
<a id="十非厄米研究的起点理论与数值为什么对不上"></a>
<a id="非厄米研究边界条件怎样逼出新的描述方法012218012915"></a>
<h2 id="non-hermitian">非厄米研究：边界条件怎样逼出新的描述方法 <span class="picks-episode-time">（01:22:18–01:29:15）</span></h2>
<p>手算与数值计算始终对不上，是这项工作的起点。姚顺宇与老师原本想研究开放量子系统的拓扑现象；手算采用周期边界，可以想成一个环或轮胎表面，数值计算采用更接近实际材料的开放边界，例如一块方形材料。两种结果的持续冲突，让他们回头检查沿用的理论假设。</p>
<p>在他的概念性解释里，孤立量子系统的演化是幺正的，对应的哈密顿量是厄米的；厄米矩阵做转置与共轭后仍与原来相同。现实材料常与环境交换信息或物质，不能总按孤立系统处理。他们研究非厄米系统，是理解开放量子系统行为的一条途径。这段口述没有展开一般开放系统的全部数学描述。</p>
<p>问题出在原本描述厄米系统时常用的布洛赫波框架。把本征态按原先的波形方式描述，在他们研究的非厄米情形中可能失效：本征态会集中到体系的一侧。于是他们建立了一套描述开放边界非厄米系统本征态的方法，再处理时间演化和动力学。所谓框架更新，有明确的问题来源、失败的旧假设和新的描述对象。</p>
<p>他把这段研究与 AI
相比，理由也很具体：有一个理解，就能设计数值实验验证；发现不符，再改理解和实现。它不是先相信理论必然正确，再给数值异常寻找借口。后文他谈学习时再次强调，如果只信手算，不重视冲突，就不会追出这个问题。</p>
<p>已有重要成果后，他却去读了几乎不相干的高能理论博士。留在原方向也许能增加论文、引用和教职机会，却不再同样令他兴奋；他想尝试自己不会的事。回头看，这种偏好也有代价。为了学习、丰富经历和能力而受困难磨炼，可以值得；“为了被折磨而被折磨”没有意义。导师没有阻拦，但他没有替导师解释内心想法。</p>
<a id="十一量子经典与蝴蝶效应先选对被观察的对象"></a>
<a id="量子与经典为什么要换一个被观察的对象012915013610"></a>
<h2 id="quantum-classical">量子与经典：为什么要换一个被观察的对象 <span class="picks-episode-time">（01:29:15–01:36:10）</span></h2>
<p>量子物理与经典物理，在姚顺宇的说明里，是不同尺度上的有效描述。可被实验检验的微观尺度用量子力学、量子场论描述，较大的时空尺度呈现经典行为。重整化群包含一个重要想法：同一根源的理论，在不同能量尺度下可能看起来完全不同。但真正的大一统理论尚未建立，更小尺度上的弦论、圈量子引力等仍不能当作已验证的事实。</p>
<p>量子纠缠可以通过两个自旋的例子理解：先制备相应状态，再把它们拉开，两者的测量结果仍有关联。薛定谔的猫与放射源，也是他用来说明关联状态的例子。实际难点不只是纸面上写出一个态，而是怎样用测量、演化和量子门把它制备出来，并保持住。粒子活在真实环境中，会遭受其他粒子和热量的扰动，状态可能很快被破坏。他顺口提及的细菌相关实验记忆不完整，不足以据此补出确定案例。</p>
<p>蝴蝶效应是另一个问题。经典系统中，一个初始小扰动的影响可能随时间指数放大；孤立量子系统却做幺正演化，两个起初接近的状态，其夹角不会这样越变越大。若只比较两个整体量子态的距离，似乎就看不到经典混沌的图景。</p>
<p>但微观量子与宏观经典应当相互衔接，不能简单认定一个世界有、另一个世界没有。姚顺宇介绍的理解方向，是考察局域可观测量的变化，而非只盯着两个整体态的距离；前者更贴近经典实验里实际观察到的差别。这段推理提醒的是先选对问题中的对象，不能把量子纠缠与蝴蝶效应混成同一个神秘现象。</p>
<p>本科物理带给他的两点收获也落在这里：读得深，比读得多更能形成新的理解；不要过度相信纯理论，要认真对待数值给出的反例。</p>
<a id="十二高能理论给他的不是失败履历而是评价标准的危机"></a>
<a id="高能理论的困境自洽之外谁来裁决013611014355"></a>
<h2 id="physics-criteria">高能理论的困境：自洽之外，谁来裁决 <span class="picks-episode-time">（01:36:11–01:43:55）</span></h2>
<p>缺少可检验的评价，是姚顺宇对博士研究最强烈的不满。他认为自己学到很多、成长很大，论文也达到外部标准，却很难说这些工作对世界产生了多少影响。问题不是混日子或做不出论文，而是满足小圈子的标准后，仍无法认可标准本身。</p>
<p>高能理论讨论的能量与微观尺度，已经远超实验所能触及的范围。没有直接实验，是否就无从推进？他先保留了合理部分：数学自洽，以及新理论在低能极限能否回到已验证的量子场论、进一步衔接经典物理，都是科学的判定方式。不能因为没有实验，就把这些工作一概否定。</p>
<p>困难在于，自洽框架可能不止一个。缺少实验区分时，谁做得好更容易依赖资深人士的主观判断。他逐渐不愿把职业生涯主要花在迎合这种评价上。博士最后两年，他开始探索量子信息、量子计算和
AI；离开学生身份、准备博士后时，选择自己道路的紧迫感更强了。</p>
<p>“伯克利博士后只做两周”也不是两周内突然改行。他在正式入职前已在那里待过两三个月，老师知道他在与
AI
公司接触，并支持在新去向尚未谈定时先保留工作。两周指正式入职到辞职的时间。</p>
<p>他也拒绝神化物理背景。工具性硬技能迁移到 AI
的部分很少，较有用的是刨根问底、系统研究的习惯；计算机、化学、生物研究者同样可能具备。履历能解释他偏爱什么工作，却不能证明物理出身天然更有优势。</p>
<a id="十三黑盒不等于无法理解智能涌现也要先定义"></a>
<a id="黑盒不等于没有理解涌现要先有定义014355014834"></a>
<h2 id="black-box">黑盒不等于没有理解，涌现要先有定义 <span class="picks-episode-time">（01:43:55–01:48:34）</span></h2>
<p>解释不到每个神经元，并不意味着什么都不知道。姚顺宇指出，物理也没有把世界从最微观机制一路完整推导到宏观表现，而是建立各尺度有效的理论。语言模型尚未达到把每个行为精确归因到某个神经元激活的“手术刀”式解释；小型、稀疏网络上的可解释性研究，不能代表前沿模型已经整体透明。</p>
<p>Scaling law
则提供另一层理解：模型大小、数据与某些性能指标如何关联，仍是可描述的经验规律。他以早期热力学作类比——经验定律可以先于对微观机制的了解，之后再形成更深入的解释。这个类比支持的是经验知识能指导研究，不是保证当前每条经验规律永远有效。</p>
<p>“智能涌现”让他更谨慎，因为说话者心里的定义可能不同。有人指模型从只会翻译、分析变得能做许多事；他更愿意讨论技术上是否找到了大规模训练、横向提升多种能力的方法。与一个缺乏共同定义的词相比，这个问题更清楚，也更便于检验。</p>
<a id="量子计算看似更近数值实验却把他带向-ai014749015228"></a>
<h2 id="numerical-experiments">量子计算看似更近，数值实验却把他带向 AI <span class="picks-episode-time">（01:47:49–01:52:28）</span></h2>
<p>了解具体瓶颈后，姚顺宇发现 AI
比量子计算更接近自己喜欢的研究。量子计算表面上沿着物理背景延伸，实际很多难点却在硬件实验：怎样实现操作、搭建平台，而非只在纸面设计算法或算子。这些工作并非他的强项。</p>
<p>AI
让他可以先提出想法，再训练模型、做数值实验，看结果是否支持理解。他不是不要实验，而是更能理解和掌握这种实验。实验室里搭光学平台，同样的基本方法，有的人能做好、有的人多年做不出，让他觉得自己尚未理解其中细节；数值实验对他更清晰。</p>
<p>他因此把 AI
类比为理论与实验尚未明显分家的早期物理：提出解释的人，也有机会自己检验解释。热的微观机制一度不清楚，却不妨碍经验规律与研究继续推进；模型内部每个矩阵元素做什么尚不透明，也不妨碍提出并测试新方法。这是他转行的研究方式依据。</p>
<a id="十四进入-anthropic赶上的是一个学习窗口不是个人传奇"></a>
<a id="进入-anthropic靠自学也靠一个特定窗口015228015838"></a>
<h2 id="joining-anthropic">进入 Anthropic，靠自学也靠一个特定窗口 <span class="picks-episode-time">（01:52:28–01:58:38）</span></h2>
<p>准备面试时，姚顺宇把能找到的材料学了一遍、作业做了一遍，又亲手训练了一个能在
notebook 里运行的小 GPT。2024
年八九月，他大致知道预训练与后训练流程，却不了解工业级语言模型的具体训练方法；当时大规模强化学习尚不成熟，团队还有许多科学和技术细节要摸清。</p>
<p>联系机会既靠主动行动，也靠原有联系。Anthropic
早期技术成员有物理背景，又吸引同背景研究者，形成了人才联系的延续。他认为这比“物理人天生适合
AI”更朴素。在他之后，几乎不再有完全没有 AI
背景的人以同样方式加入，说明这个入口也有时机限制。他同时联系过 OpenAI 和
DeepMind，前者未找到特别合适的事与人，后者当时流程较慢。</p>
<p>面对评测与强化学习两个方向，他选了更不明朗的后者。按他的回忆，入职时
Horizon
大团队约十到十一人，公司约七八百人；组内有数据、环境、基础设施和研究算法等不同工作，他在偏研究与算法的小组。</p>
<p>小团队、彼此熟悉、愿意分享，使他能接触训练链条的多个环节，并找到相应的人请教。这是他反复强调的学习价值：有机会触摸完整系统，再逐步弄懂各部分怎样协同。能独立学材料很重要，真正进入这种环境同样不可替代。</p>
<a id="十五两类组织打法押注与储备以及技术领导的责任"></a>
<a id="组织怎样下注先捕捉信号再承担选择的后果015838020838"></a>
<h2 id="organizations">组织怎样下注：先捕捉信号，再承担选择的后果 <span class="picks-episode-time">（01:58:38–02:08:38）</span></h2>
<p>Claude 3 发布后，外部有人反馈它写代码比当时的 GPT-4
更好；公司捕捉到信号，迅速投入。这是姚顺宇所见 Anthropic
押注编程的一个来源。他不能完整公开最初的技术原因，也不确定一开始是随机尝试还是刻意选择。能肯定的是，从可能自下而上的发现，转成自上而下资源投入的速度。</p>
<p>技术决策者要让研究员信服，也要有权代表公司承担风险，两者缺一不可。他认为技术创始成员同时具备这两项条件，让
Anthropic 的强执行成为可能。至于最高层每次讨论时 CEO
与其他人如何分工，他没有足够视野，不把推测当内幕。</p>
<p>团队长期共同工作带来的信任也很关键。早期成员参与过多项相同的关键研究，能一起承担下注的后果；如果创始小集体都难以维系，要求大组织团结就更难。这里的判断依赖共同经历，不只是“找一个最聪明的人”。</p>
<p>创业公司要明确押注、快速推进，大公司则可以广泛储备：别人某个方向成功时跟上，自己做成时领先。因此他不要求
Google 复制同一打法。关于 Google
预训练后来如何明确负责人、节点与评价，见<a href="detail.md#engineering">工程组织</a>；那部分也修正了把 Google
一概称为自下而上的概括。</p>
<p>他的第一个主要模型项目是 Claude 3.7，几乎没参与 3.5
的后续版本。他特地解释，3.5
曾有两个版本，外界为区分才把后一个叫作“3.6”；不能把他工作期间前后的全部成果都算成个人履历。入职时团队已看到编程重要且能做，接下来的任务是共同研究怎样把规模做上去。</p>
<a id="claude-37-的分水岭是把后训练稳定做大020840022148"></a>
<a id="十六claude-37-的分水岭不是神秘技巧而是稳定扩大后训练"></a>
<h2 id="post-training">Claude 3.7 的分水岭，是把后训练稳定做大 <span class="picks-episode-time">（02:08:40–02:21:48）</span></h2>
<p>找到能持续供给任务、提供清楚反馈的环境，并在其上稳定训练，是姚顺宇对这次分水岭的概括。此前后训练更多是小规模修补，后来才找到扩规模的方法：奖励足够客观，环境是强数据源，数据干净、任务对模型可学习，训练又能维持稳定。知道“用强化学习”，远不足以把这些条件做实。</p>
<p>“把简单的事做得比谁都干净”，也不是只许用最简单算法。他举 policy
gradient
与复杂搜索方法作对照：复杂性可能提高效率，也可能带来基础设施困难。研究要比较效果、稳定性和实施成本，选适合系统的一条路，而非以技巧数量论高低。</p>
<p>编程在这里有双重价值。一方面，研究模型本身需要写代码，编程能力提高有望加速模型研究；另一方面，清晰反馈与充足任务环境，让编程成为研究工具使用、环境交互的好载体。从这里学到的东西，可能推广到更一般的交互任务。这种研究效率循环，与前面尚未观察到的应用市场数据飞轮，是不同概念。</p>
<p>不同公司并没有采用完全相同的具体实现。他后来了解到，OpenAI 与
Anthropic
的算法、使用数据的方式差别很大，共同方向却相近，也都能做成。自己刚入行时也曾接受“预训练的金矿快挖完了”的叙事，了解深入后才觉得仍有空间。Scaling
law 不只是要求模型一直变大，更是选择有效配置的系统框架。</p>
<p>于是，“平台期”也要拆开：是还有想教的能力却技术上教不会，还是人还没想好下一件该教什么、怎样教？他当时更担心后者。这延续了开场的判断：模型像一个学习能力很强的孩子，但老师还需要把下一道题定义好。</p>
<p>他回忆，从为项目做研究到发布大约四五个月：前期研究两三个月，训练和新的基础设施又约两个月，中间有不少困难。他的工作涉及
Agent 编程环境、数据与算法。这个过程远不是在现成系统上按一次启动键。</p>
<p>为什么不能照抄某公司的小技巧？生成轨迹和 token 的
sampler，与更新权重的
trainer，可能因数值实现和异步训练架构产生差异。某公司的偏差很大，算法首先得控制偏差、保证稳定；另一家基础设施较好，才有余力更多优化训练效果。一个技巧可能只是修补特定系统的瓶颈。不了解全系统，知道“它有效”仍可能被误导。</p>
<p>从 3.7 到
4.5，他概括为预训练与后训练继续推进，数据和计算规模更大，没有再次出现同等程度的范式变化。</p>
<a id="十七离职预测失准与阶段目标学习和产品影响并非一件事"></a>
<a id="换工作先分清此时要学习还是要直接影响产品022148022931"></a>
<h2 id="career-choice">换工作先分清：此时要学习，还是要直接影响产品 <span class="picks-episode-time">（02:21:48–02:29:31）</span></h2>
<p>研究自由、横向学习与明确的个人产品范围，不总能同时最大化。姚顺宇认为，如果最在意把自己的某个想法直接送入最终模型，大而成熟的
Google 未必合适；如果想接触广泛研究方向和高手、学习不同技术，Gemini
对他很有吸引力。有些换工作后的失落，来自入职前说想学习，进去后却最在意个人产品影响。</p>
<p>离开 Anthropic
有几个原因。他回忆公司一年内从约七八百人增长到接近两千人，原先熟悉、直接的小作坊氛围受到文化磨合的冲击。他个人不喜欢过多宣传，或在
Slack
上讲大道理却不把想法拆成步骤做出来；同时也承认，不喜欢某些人的方式，不代表那些人一定不好。</p>
<p>另一个原因是想学更广的东西。Anthropic
专注语言模型、工具和编程，适合纵向理解一条线；多模态生成、更底层工程等方向，当时不是他在那里容易接触的工作。他还表达了对
CEO
涉华表态的反感，认为作为公司负责人把观点推得过于极端、情绪化并不合适。这是他的个人评价。</p>
<p>被问这一项占多少比例，他提到“40%”，随即说数字“听听就好”：它不是主导一切的原因，但也不能忽略。这个回答表达权重感受，不适合画成精确归因图。学习与产品影响的优先级以后也可能变化，他没有给自己设定永远不变的选择。</p>
<p>个人贡献同样要分清可说明的部分。他愿意讲自己做过哪些环境工作、怎样改进训练稳定性，也承认算法虽有提升，却未达到特别理想的效果，而且是集体贡献。把这些技术效果换算成最终模型里个人占多少份额，他认为很难客观量化。</p>
<a id="二十一英雄主义已过去有边界安全也不能只靠一家公司的意志"></a>
<a id="英雄主义的阶段边界与单家公司安全承诺的边界022931023540"></a>
<h2 id="heroes-safety">英雄主义的阶段边界，与单家公司安全承诺的边界 <span class="picks-episode-time">（02:29:31–02:35:40）</span></h2>
<p>可扩大规模的路线尚未被找到时，一个人或小团队可能改变进程；路线跑通后，语言模型的推进越来越依赖多环节共同工作。这是姚顺宇说“个人英雄主义时代”过去时的范围。Transformer
等关键突破属于他认可的英雄集体；没有那个发现，进展可能推迟很久。他没有否认所有阶段、所有领域中的个人作用。</p>
<p>规模化之后，他认为许多想法并不神秘，难的是组织一起把事做成。编程方向的公司级快速下注仍有价值，但即使某一家不做，也可能有别家推进。这种判断又引出
AI
安全的难题：一家停止发展，其他公司仍会继续，停止者反而可能失去话语权。</p>
<p>他把 Anthropic
的一项安全思路概括为，先拥有最前沿的模型，再取得推动安全政策的话语权，并对此持批评态度。若多家都有前沿模型，单方安排就很难让所有人接受。这是他对公司思路的理解与评价，不是访谈给出的一份完整政策文本。</p>
<p>他以多个有核国家相互制衡作类比，认为可能需要多方约束，才有机会限制危险行为。类比表达的是制度直觉，尚未构成可执行、已验证的
AI 安全方案。技术难靠一家叫停，与安全需要约束，这两个要求同时存在。</p>
<p>谈到可解释性，他也只提小型、稀疏网络中研究内部表示、修改表示后观察输出的工作，没有声称前沿模型已经被全面解释。</p>
<a id="ai-自己做研究要能用结果决定下一次实验023453023800"></a>
<a id="十八ml-coding要闭合的不是代码生成而是研究循环"></a>
<h2 id="ml-research">AI 自己做研究，要能用结果决定下一次实验 <span class="picks-episode-time">（02:34:53–02:38:00）</span></h2>
<p>关于 AI
本质上简单的说法，姚顺宇首先把它限定为可对可错的个人陈述。他被追问后给出的理由，是与高能理论相比，AI
中很多想法能够实验检验：缺少的可能是算力、基础设施和时间，而不是永远拿不到某个能标下的数据。尚未完全理解，也能继续试。它没有推出所有
AI 难题都已解决。</p>
<p>他接着说 AI
很快会开始自己做实验。主持人问是不是四个月内，他回答未来六到十二个月，又立即承认这句话“不太良好定义”，随之收窄范围。AI
帮人实现想法、加速实验已经发生，不能把这一事实算作未来预测的兑现。</p>
<p>更严格的目标，是从头到尾完成一项 AI
研究：写代码、运行实验、查看结果、分析哪里不对、提出新的假设，再设计新的代码与实验。当时这条链还没有完整打通。他预测的是这个循环逐渐完整，而非单次生成更多代码。</p>
<p>这也使“AI
做研究”有了可追问的标准：一次实验跑完后，下一条值得检验的假设来自哪里？模型若只执行人的方案，还停在辅助环节。后文<a href="detail.md#long-horizon">长期工作</a>中的 ML
coding，正是沿着这个目标研究数据、反馈与基础设施。</p>
<a id="一次判断修正效率产品改变了他对-anthropic-的预期023714024151"></a>
<h2 id="product-correction">一次判断修正：效率产品改变了他对 Anthropic 的预期 <span class="picks-episode-time">（02:37:14–02:41:51）</span></h2>
<p>离开时，姚顺宇对主要靠 API 卖 token
的生意比较悲观。他认为最终会打价格战，没有完整链条的公司处于劣势，Google
更有条件承受竞争。后来 Claude Code、Cowork
等围绕工作效率的产品发展起来，他承认自己“过度悲观了”。</p>
<p>承认公司判断失准，并没有让他否定个人选择。他换环境的主要目标是学习，而这件事达到了预期。对公司的收入形态怎么看，与个人在哪个阶段需要什么，并非同一个问题。</p>
<p>产品也给“个人英雄主义”留下了例外。在他的理解里，Claude Code
的开端，是有人想提高自己和同事的效率，后来才成为对更多人有用的工具。交互方式的变化，可能比简单摆放功能更有价值，他也以抖音的交互变化作类比。但他与相关负责人私人接触不多，已经离开后更没看到
Cowork
的发展过程。被追问两个产品是否都出自同一人时，他明确说不知道，不能把功劳合并到一个名字上。</p>
<a id="十九long-horizon有限上下文怎样支持长期工作"></a>
<a id="有限上下文怎样支撑长期研究与长期助手024106024714"></a>
<h2 id="long-horizon">有限上下文怎样支撑长期研究与长期助手 <span class="picks-episode-time">（02:41:06–02:47:14）</span></h2>
<p>把研究任务拉长，不必等于把每条训练序列无限拉长。姚顺宇更感兴趣的是，模型怎样在有限上下文里持续工作：不重要的内容先移除，重要信息放到外部存储，在需要时再取回。</p>
<p>他以人的记忆作类比：此刻想不起昨晚吃了什么，可能只是那件事与当前问题无关；人会选择性遗忘，也能重新检索相关信息。长期助手如果能持续认识用户，又有这种筛选与取回能力，就可能完成单次短对话做不到的任务。这个类比表达研究直觉，不是宣称人工记忆与人的记忆机制相同。</p>
<p>公开可谈的方案有两类。一类从预训练和模型计算机制入手，如稀疏
attention；另一类从后训练与上下文管理入手，让模型删去不重要段落，把重要内容存到文件，以后再读回来。实际实现不止这些例子，各家仍有细节需要研究。</p>
<p>他主要投入后一类。一个原因是已有后训练经验，另一个原因是自己的目标正是用短的上下文训练、完成更长的工作；有些预训练方案仍要求长上下文数据，并不完全贴合这个目标。他也澄清，预训练更多是自己想学习的兴趣，并非正式工作中投入很多的领域。</p>
<p>ML coding 与 long horizon 因而互补。Agent
编程已经包含工具使用和计算机环境交互；AI
研究横向增加了新场景，又纵向拉长工作时间，一项完整研究远比代码补全持续得久。他把这称作“T
字形”的延展。要训练这种能力，就需重新处理选什么数据、怎样定义奖励、怎样建设基础设施的问题。</p>
<p>能做与哪条路线最有效，仍是两回事。他认为用短上下文支持长期工作可行，但需要科学比较不同方案。前段<a href="detail.md#finite-context">2026
年内实现的预测</a>并没有消除这个未知，也没有承诺无限保存全部历史。对
Gemini
长文本表现，他承认预训练与后训练都有贡献，并保留有人觉得新版本某些体验反而下降的不同反馈。</p>
<a id="二十模型赶上之后获客产品与搜索需求仍需分别讨论"></a>
<a id="模型追上之后还要分别解决获客留存与搜索需求024714025929"></a>
<h2 id="google-search">模型追上之后，还要分别解决获客、留存与搜索需求 <span class="picks-episode-time">（02:47:14–02:59:29）</span></h2>
<p>模型单独变好，不一定立刻改变市场。姚顺宇对 Google 转折的解释，是 Nano
Banana 的爆款先吸引用户下载应用，随后 Gemini 3
留住其中一部分人。用户基数很小时，能力提高传播得慢；获客与留存接在一起，影响才更大。他随口估过约
20% 的份额，同时明确没有仔细查数据，因此不能拿它证明市占率。</p>
<p>他觉得业内对 Gemini 的观感在 2.5
这一代已经变化，但自己的加入不是追逐版本热度。与团队交流后看到的研究自由、工程能力和学习机会，才是个人选择的依据。OpenAI
也是当时的选项，他对其做事文化有担忧；这仍是择业印象，不能扩写成对全体员工的测量。</p>
<p>他甚至认为 OpenAI 某种程度上救了
Google。这是一种反事实解释：聊天机器人先证明威胁真实存在，却没有迅速把搜索完全替代，让
Google
获得反应和追赶的时间。主持人追问，是竞争者没做好，还是聊天形态本身做不到？他回答两方面都有。</p>
<p>聊天适合追问、浓缩复杂信息，这部分会替代搜索；简单需求却未必需要对话。他举“买大米”为例，直接搜、直接买即可；若先等模型思考、给链接，再跳网页购买，反而多走一段。当前对话形态覆盖不了全部搜索需求，竞争者执行也没有做到让别人完全无法追赶，两者可以同时成立。</p>
<p>模型赶上不等于产品与品牌赶上。他认为 Google
传统上产品动作较慢，却擅长在简单形态里把技术做到极致：搜索同样是一个框、一个按钮，仍能在速度和准确性上形成差别，背后是重视工程师与研究的氛围。</p>
<p>至于聊天机器人是不是最终的超级应用，他没有理性或量化标准，只觉得模型能力很多，主要靠对话框调用，尚未充分释放。被问下一种形态是什么，他也直说没想明白。这种不满足可以推动寻找新产品，却不足以证明某种替代界面已经成立。</p>
<a id="确定的训练路线需要明确节点与评价框架025844030146"></a>
<h2 id="engineering">确定的训练路线，需要明确节点与评价框架 <span class="picks-episode-time">（02:58:44–03:01:46）</span></h2>
<p>预训练在 Google
变得更清楚，是姚顺宇看到的组织变化：谁负责什么、下一阶段目标是什么、哪些节点必须处理、研究结果怎样评价，都有明确框架。他把这称为将较确定的范式做成工程项目。技术储备与系统的工程管理结合，让后续进展更可预测。</p>
<p>这也修正了“Google 自下而上、Anthropic 自上而下”的简单二分。Google
的预训练同样有很强的自上而下安排；后训练不确定性更多，才保留更广泛的自主探索。他没有经历更早的混乱，相关说法来自同事和旧识，而非自己的全程观察。</p>
<p>组织方式应当随工作改变。路线已较明确时，需要把责任和检验方式做扎实；还不知道最佳做法时，则需要允许更多尝试。两种公司都可能成功，并不能推出组织机制可以不顾阶段随意互换。</p>
<a id="预训练sft-与-rl他为何更看重数据分布差别030101030456"></a>
<h2 id="training-distribution">预训练、SFT 与 RL：他为何更看重数据分布差别 <span class="picks-episode-time">（03:01:01–03:04:56）</span></h2>
<p>从姚顺宇的宽泛概括看，预训练与监督微调把给定数据当作专家输出，让模型靠近这个分布；强化学习可以使用自己生成的结果，增加好结果、远离坏结果。在这个意义上，他把前两者视为强化学习的一种特殊情形。这是他的解释角度，不是取消实践中的方法区别。</p>
<p>就当时的训练实践，他更看重数据分布：预训练要足够广，覆盖想要的范围，不要求每条数据都达到极高质量；后训练可以窄得多，但已有数据的质量要求很高。因此讨论两者，不能只看算法名称，还要看拿什么数据、教什么行为。</p>
<p>不同公司切分团队的方式也不完全相同。他对工作过的公司更熟悉，对未任职公司的理解则来自间接信息，且组织后来变化很多。有的团队把部分后训练与产品放得更近，可能让产品需求直接影响训练；他没有据此给出一张可靠的当前组织图。</p>
<a id="分数接近饱和之后新目标比争第一更重要030456031021"></a>
<h2 id="benchmarks">分数接近饱和之后，新目标比争第一更重要 <span class="picks-episode-time">（03:04:56–03:10:21）</span></h2>
<p>姚顺宇用冲浪形容个人与行业的关系：“本质上是那个浪，而不是你那个冲浪的人。”AI
本身在推进，个人恰好赶上机会。他能说明自己参与了算法细节讨论、数据等工作，却不认为报道把最终模型归到少数名字上是准确的表达。</p>
<p>他没有把近期模型每次发布都看成范式跳变。相较从不知道如何做大规模强化学习，到能把它做成的那次变化，后来的不少改进仍在既有方向内。内部细节没有公开的部分，他也没有在访谈中披露。</p>
<p>他质疑的是继续争公众熟悉的基准第一，是否还最值得关注。编程评测已普遍到八成以上；他提到“83”附近及某些题目定义不良的转述，也回忆一类抽象推理评测从十几分到三十多、六十多，再到八十多的快速提高。这些数字带有版本记忆的犹疑和未核验的转述，呈现的是他眼中的饱和趋势，不能拼成精确排行榜。</p>
<p>他更关注 ML coding 和 long
horizon，但没有把它们自动封为已到来的新范式。Google
从硬件设计到模型训练有较完整的 AI
研究链条，若能加速这些环节、让它们管理得更好，价值就很大。寻找新的目标与评价，并不意味着基础能力从此无须关心。</p>
<a id="持续学习与世界模型先说清希望系统做到什么031021031327"></a>
<h2 id="continual-world-models">持续学习与世界模型，先说清希望系统做到什么 <span class="picks-episode-time">（03:10:21–03:13:27）</span></h2>
<p>持续学习和长期工作，在姚顺宇看来未必有根本不同的目标。常见区分是：持续学习会改变模型权重，上下文管理不会。但上下文对应的
KV
等状态也承担信息存储作用，所以他不愿过早断定哪条路径长期更有效。这是关于目标与存储作用的类比，不是证明权重更新与上下文管理在算法上等价。</p>
<p>“世界模型”则缺乏一致定义。他介绍的一类 Gemini
探索，不仅是给定描述生成视频，而是生成一个场景状态；再给定在这个状态采取的动作，让下一状态由此前状态与动作共同决定，并端到端训练这种能力。</p>
<p>这个例子说明了状态、动作和转移的关系，却不能代表所有团队。他不了解外部实验室全部细节，也不知道大家最终期待的结果是否一样，因而认为还在探索。多模态生成等更不确定的方向，仍可能出现关键个人或小团队带来的突破。对紧接着被问到的
xAI 动荡，他则承认接触有限、不了解原因，没有提供内部因果解释。</p>
<a id="二十二靠谱如何落到可检验的技术比较"></a>
<a id="靠谱的算法比较要把采样成本和全局瓶颈算进去031327032152"></a>
<h2 id="research-reliability">靠谱的算法比较，要把采样成本和全局瓶颈算进去 <span class="picks-episode-time">（03:13:27–03:21:52）</span></h2>
<p>一种强化学习算法曲线更好，研究者还应继续问：大规模下同样稳定吗？是否换了更好的数据？是否花了更多训练
FLOPs，或者更多采样
FLOPs？最终生产运行真正受限的资源是什么？姚顺宇用这些问题把“科学态度”和“靠谱”变成具体工作。</p>
<p>反例是只报有利于自己的成本。如果只算训练时方法占优，加上采样成本后就不占优，却仍只展示训练指标，组织会被好看的数字误导。遗漏可能有意，也可能因为研究者没理解全局。因此，一方面要个人主动审查自己的正结果，另一方面要组织建立足够严谨的评价体系，发现这些遗漏。</p>
<p>他认为，公司研究者的责任不止于一个项目可重复，还包括理解它怎样影响整个系统。如果局部改善没有缓解真实瓶颈，价值就需要重新判断。只为个人英雄叙事做事，可能破坏这种整体性；真正能力强、确实解决了问题，则是另一回事。</p>
<p>把组织全部交给自由探索也不够。完全自下而上可能让人连自己工作的用途都不清楚，领导要能把方向与自主性结合起来。他提出两个要求：关键困难发生时，有能力亲自下场带人解决；对自己不做的方向，也能理解其重要性、容得下别人。领导不必一直救火，却不能只有口头要求，是否叫
CEO 不是核心。</p>
<p>谈 Google 高层分工时，他描述了自己看到的创始人支持拍板、CTO
更多参与技术一线、部分管理者更关注科学方向的情况，同时承认还有许多看不到的部分。这些观察能说明技术领导的作用，不能当作完整权责图。</p>
<a id="gpu-与-tpu-的比较离不开规模和配套系统032107032414"></a>
<a id="二十三硬件新实验室与新人机会不要脱离规模和阶段"></a>
<h2 id="hardware">GPU 与 TPU 的比较，离不开规模和配套系统 <span class="picks-episode-time">（03:21:07–03:24:14）</span></h2>
<p>硬件不能脱离生态与部署规模判输赢。GPU
的开放生态让独立团队使用方便；Google 为 TPU
自建基础设施，成本在大规模部署时更容易摊薄。同样的建设投入，放在一千张卡上是很大负担，放在几十万张卡上就不同。</p>
<p>姚顺宇用自己较熟悉的一代 GPU
作例子：小组内如八张卡通过高速互联，组内通信阻力很小；TPU
则更偏向把大量卡连进较大的三维 torus
拓扑。若编译器和切分逻辑适配得好，就可能利用更大范围的存储、减少通信瓶颈；代价是在小规模上结构更固定，通用性和易用性未必占优。他没有充分使用后面几代
GPU，这些例子不能推广成所有代际、任务的结论。</p>
<p>对不断出现的新实验室，他整体悲观，却也承认有些团队在交付新东西。对另一些团队不清楚它们想做什么，并不等于掌握了其必败的证据；字幕被隐去的人名也不足以识别对象。</p>
<a id="中美产品取向的不同也来自不同的商业反馈032414032851"></a>
<h2 id="consumer-products">中美产品取向的不同，也来自不同的商业反馈 <span class="picks-episode-time">（03:24:14–03:28:51）</span></h2>
<p>美国企业与效率软件市场大、盈利路径直接，是姚顺宇解释产品取向的主要原因。帮用户提高效率，可以按服务能力收费；他用“成本
150、卖 200、赚
50”作示意，强调这种直接关系，而非给出某个产品的真实报价。</p>
<p>中国消费者产品则积累了更长的变现链条：先让用户免费看内容，再通过广告、直播、电商获得收入，未必每次使用都直接付费。一旦这个循环形成，后来者想插入生态会很难。他认为这与过去多年商业环境给予的反馈有关：容易通过企业软件挣钱的市场，不一定迫使团队设计同样复杂的消费者产品。</p>
<p>他很看重字节的产品能力，也觉得美国团队尚未充分理解它。这个评价解释的是他的观察与偏好，不能据此把全部中国公司、美国公司划为两种固定类型。他关于模型上限、语音体验和日常交互的判断，也应放回具体用户与商业场景理解。</p>
<a id="24-小时项目与一小时答辩检验人是否理解-ai-的工作032851033412"></a>
<h2 id="ai-collaboration">24 小时项目与一小时答辩，检验人是否理解 AI 的工作 <span class="picks-episode-time">（03:28:51–03:34:12）</span></h2>
<p>姚顺宇设计过一道面试题：给定计算资源，让候选人在 24
小时内自己选模型、数据和算法，从零做出一个强化学习项目；结束后再讨论一小时。AI
已能帮助完成大量代码，所以他觉得继续主要考手写代码，未必贴合实际工作。更该看的是候选人能否借工具把事做成。</p>
<p>完成项目还不够。如果把所有事情交给模型，却没弄懂 AI
做了什么，随后的讨论就会暴露问题。能否解释实现、选择和结果，才让协作与全盘代办区分开。这对应他反复强调的可靠、细心和负责，而不是生成了多少行代码。</p>
<p>他也坦白，设计成 24
小时还有观察候选人多看重机会、是否愿意熬夜的想法。这是个人招聘偏好，访谈没有证明它普遍有效或公平，不能把它作为唯一的人才标准。</p>
<p>“AI
不太需要脑子”的激烈表达，要放在他反对神化个体的语境里。他认为，既定范式中不少工作并非只有天才能做，但培养一个研究者需要实际环境：得有机会接触系统，才能学会。高价人才的一部分稀缺可能来自这种训练机会少，而非每个人都不可替代。他本人受益于市场价格，也仍担心炒作过度。</p>
<a id="新人寻找的机会不必就是当下最热的方向033326033937"></a>
<h2 id="newcomers">新人寻找的机会，不必就是当下最热的方向 <span class="picks-episode-time">（03:33:26–03:39:37）</span></h2>
<p>纯语言模型不再是他入行时的蓝海，失去的是一种特定窗口：在尚不庞大的团队中接近完整链条、共同摸索关键做法。姚顺宇把自己那次机会称作“末班车”，却没有据此劝年轻人放弃整个
AI。多模态生成、机器人、AI
帮助科学问题乃至量子调控，都还有大量未被做成的事情。</p>
<p>他的建议是，不要自动把最热门的方向视为最有机会的方向。年轻人可以找尚未被做成的事，同时弄懂其中真实瓶颈。知道与不知道系统细节之间，仍有很长的学习距离；这也解释了他为什么仍愿意在自称“本质简单”的领域投入时间。</p>
<p>他对自己的未来没有确定路线，也不觉得会永远留在同一大公司。Anthropic
给了他沿语言模型一条线深入的纵向学习，Google
则带来更多方向、人员与视角。眼下最高优先级，是和同事把 ML coding、long
horizon 推进到较稳定的状态。用 AI
做物理已有许多人在试，暂时不是他自己的最高优先项。</p>
<p>他并非从不欣赏英雄。谈起在当年显得格格不入、坚持多年后才被理解的物理研究者，以及早期长期坚持
AI 方向的人，他强调的是非共识时期的远见与持续工作，也再次认可
Transformer
这样的英雄集体。这里的关键仍是阶段与具体贡献，不能缩成“历史上从无英雄”。</p>
<a id="二十四结尾仍回到同一要求让判断有可能被证明错"></a>
<a id="最后的要求说清一个判断可能怎样被证明错033938034753"></a>
<h2 id="testable-claims">最后的要求：说清一个判断可能怎样被证明错 <span class="picks-episode-time">（03:39:38–03:47:53）</span></h2>
<p>一种说法若能适配任何未来结果，就很难判断对错。姚顺宇尤其反感这样的表述：无论以后出现哪种范式，说话者都能声称自己早已预言。他批评的核心是定义模糊；相反，目标与方法明确的路线，即使自己不赞同，也至少能交给未来检验。对被隐去的人名，材料不足，保留论证即可。</p>
<p>直言也不等于随意攻击。他区分两类资深者：一种少干涉、愿花力气培养年轻人；另一种自己不了解，却喜欢指点。反对的是权威姿态，不是年龄本身。他认为表达要有自己的理解，能讲清依据，才有可能获得尊重。</p>
