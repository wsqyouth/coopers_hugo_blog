## 核心心智模型：可信的是完整测量过程

可信评测必须让分数背后的数据、系统、评分器和统计口径都能被检查。HELM 的方法论价值，是把场景与指标展开、控制比较条件，并明确未覆盖之处。Agent 评测还要把工具、执行框架和环境算进被测系统：一句“已完成”，与环境中确实出现正确结果，是两种证据。

推断：读评测报告时，可以沿这条链逐项追问。它是一种审阅方法，不是经过验证的“可信度总分”；任何一环缺失，都要缩小结论的适用范围。

## 洞察一：先界定被测对象，分数才有含义

模型能力、系统完成任务的能力和用户偏好，是三个不同的测量对象。HELM 强调在尽可能一致的场景与适配策略下比较语言模型，同时衡量准确性以外的指标。MT-Bench 与 Chatbot Arena 则把多轮对话中的人类偏好带入评测。两类结果可以互补：知识题答得好，不自动代表用户更喜欢回答；用户喜欢，也不能替代功能正确性验证。

到了 agent，工具接口、提示词、权限、运行框架与环境都会影响结果。预订航班是否成功，应检查预订状态；编程任务是否完成，应检查实现是否满足功能要求。执行记录帮助解释为什么成功或失败，但记录里声称“已完成”，不能替代结果核验。

推断：比较两个 agent 方案时，应先确定要测“固定模型下的编排差异”，还是“完整系统在同等成本下的表现”。前者尽量控制其他条件；后者允许实现不同，但要计入各自全部成本。将两者混在一起，就难以归因。

最终状态也不覆盖所有要求。若任务规定不得越权、不得泄露数据，正确终态仍需与这些行为约束一起评价。约束应来自任务，而不是要求 agent 逐步照抄评测者预想的工具调用路径。

## 洞察二：污染需要证据，“没查出来”也有边界

基准污染会让成绩难以区分泛化能力与对测试材料的记忆，但高分本身不是污染证明。直接检查可得训练数据中的测试重叠是一类证据；黑箱场景下则需要在明确假设下做检测，不能把怀疑直接写成结论。

Oren 等人的方法利用数据集样本顺序的可交换性：在相应独立性假设下，模型不应特别偏好公开仓库中的规范排列。检验比较规范顺序与打乱顺序的序列对数概率。它无需训练数据或权重，但需要序列概率查询；“黑箱”不等于只拿到聊天输出就能直接运行。其误报控制依赖假设，检出能力也有边界。

另一项原始研究展示了字符串去重的缺口：改写、翻译后的测试样本可能绕过 n-gram 重叠过滤。因此，去掉逐字重复并不足以证明测试完全干净。反过来，检测无显著结果，也可能意味着方法没有足够检出能力，不能直接解释为不存在污染。

推断：工程上应组合保留测试集、数据来源和时间记录、逐字与语义重叠检查，并把新鲜任务作为补充验证。持续拿测试结果调提示词、改流程，会使测试集逐渐承担开发集的角色；应另外保留未参与调整的验证材料。新任务也不必然与旧任务同难度，因此新旧分差仍不能单独证明污染影响有多大。

最实用的报告语言是分清“发现了重叠”“检测提示依赖”“尚无充分证据”，而非只给一个“已去污染”的标签。

## 洞察三：LLM 评分器要先被校准

LLM-as-judge 能扩展评价规模，但它评价的是某个标准下的输出，而非天然正确的真值。原始 MT-Bench 研究讨论了位置偏差、冗长偏差、潜在的自我偏好及推理能力限制，也在特定实验中发现较强评分器与人工偏好有较高一致性。这支持其作为偏好评价的工具，不构成它在任意任务、语言或领域都能代替专家的保证。

位置偏差意味着交换 A、B 顺序可能改变判断；冗长偏差意味着内容未改善、篇幅变长也可能更受青睐；论文中的“自我偏好”指评分模型可能偏爱自己生成的回答；受数据有限、差异较小的限制，该研究尚不能确定受测模型是否存在这种偏差。若评分任务需要先解决困难问题，评分器自身的解题错误也可能影响裁决。

两家官方指南都强调清楚的评分标准及人工校准。能用程序验证的事实，可以优先检查程序结果；开放式质量则拆成具体维度，提供参考答案或档位例子。信息不足时允许评分器回答“无法判断”，优于强迫它猜一个分数。

推断：一个最小校准过程可以先选一批覆盖典型、边界和失败案例的材料，由人工独立标注，再比较模型评分；成对比较时交换回答顺序，并单看分歧案例、不同类别及不同长度的结果。隐藏被比较方案的身份、固定 judge 版本和 rubric，能减少不必要的变化。更换评分模型或标准后，需重新验证一致性。

多位模型评分器达成共识，可以增加观察角度，却不能单凭“票数多”证明结论正确。推断：若它们共享相似训练数据、参考材料或评分标准，错误可能相关；独立上下文可以隔离对话历史，不能自动保证统计独立或认知独立。

## 洞察四：pass@k 说的是机会，不是单次可靠性

pass@k 衡量同一道任务在 k 次尝试中至少成功一次的概率。它适合表达有重试机会时的解题覆盖能力；只报告很大的 k，容易掩盖一次交付是否可靠，也没有说明用户怎样找到那个正确答案。

若某题每次尝试的成功概率为 p，且各次独立、采样策略相同，则：

\[
\mathrm{pass@}k=1-(1-p)^k,\qquad
\mathrm{pass}^{k}=p^k.
\]

前者问“至少一次成功”，后者问“k 次全部成功”。例如，**纯示意**地令 p=0.5、k=3，则两者分别为 0.875 与 0.125；这不是模型实测数据。两种数值都没有错，它们回答不同产品问题。

实际任务难度不同，各题可能有不同的成功概率，应先按题定义和估计，再汇总。不能直接把所有任务的平均单次成功率代入上式，冒充整个任务集的 pass@k。相互依赖的修复回合、共享历史的尝试，也不能不加说明地当成独立抽样。

Codex 论文给出一种常用估计方法：某题共生成 n 个样本，其中 c 个通过测试，且 n≥k，则按题计算：

\[
\widehat{\mathrm{pass@}k}
=1-\frac{\binom{n-c}{k}}{\binom nk}.
\]

其中 n−c<k 时，分子按 0 处理。这可以理解为：从已有 n 个样本中无放回取 k 个，至少选中一个成功样本的比例；当这 n 个样本来自固定分布的独立采样时，它是目标 pass@k 的无偏估计。论文指出，将经验成功率 c/n 直接代入 1−(1−p)^k 会带来偏差。实际比较仍要固定任务、正确性标准、采样设置和预算，并报告 n、k 与汇总方法。

对 agent，还应区分“一次 trial 内允许修复”与“重开一个 trial”。前者是被测系统的运行策略，后者是重复试验。环境残留、缓存或前次 git 历史会造成额外信息和相关性；每次试验应从约定的干净环境开始。

推断：产品报告至少并列呈现单次表现、允许重试后的表现、总成本和最终答案选择方式。一个正确答案是否存在，与系统能否可靠选出并交付它，是两个需要分别验证的问题。

## 洞察五：人评一致性检查的是标准，不是事实本身

人工评价也需要明确定义、独立标注和分歧分析，不能只写“经人工审核”。首先应拆开事实正确、任务完成、表达清楚等维度，再给每个维度可操作的定义及评分例子。参与者是谁、理解什么领域、看过哪些信息，都会影响结果。

一致性指标衡量不同标注者判断的吻合程度。原始一致率直观，但没有扣除由标签分布带来的机会一致；Cohen’s κ 用机会一致作校正。序数评分可考虑加权 κ，多标注者或不同数据结构可考虑 Fleiss’ κ、Krippendorff’s α 等，但选择必须匹配标注设计与尺度，不能跨指标套用同一个“及格线”。

人评方法文献建议同时报告一致性、百分比一致率与置信区间，交代样本和实验设计，并减少呈现顺序、学习效应等影响。高一致性表明判断较稳定；大家也可能一致误解题意或共同缺少领域知识，因此它仍不能替代正确性和目标效度的验证。

推断：先独立标注一批材料，再计算一致性、复查分歧并修订评分规则；之后用新的校准材料验证规则。最终裁决可以形成参考标签，但应保留裁决前的独立判断。直接拿讨论后的统一意见计算一致性，会掩盖原先的分歧。若分歧反映合理的用户偏好差异，应保留分布或分人群报告，而非强行制造唯一真值。

对主观质量，人工参考标签与模型评分器之间的一致性，是校准证据；对可验证事实，仍应回到外部事实或可执行检查。二者服务于不同目的。
