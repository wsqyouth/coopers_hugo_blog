<h2 id="摘要">摘要</h2>
<p>一个训练任务没有宕机，却可能已经算错：梯度指数上的一位翻转，就能把
0.2 变成 10²⁰，再随同步训练传播出去。Jeff Dean 用这个例子说明，AI
的进步不只发生在模型架构里。更大的计算规模、更有效的学习算法、能识别并替换坏硬件的训练系统，以及降低推理成本的方法，要一起工作，才能把更强的模型变成可用的服务。</p>
<p>这场演讲从早期神经网络讲到
Gemini，再走向团队协作和未来研究。它解释了为什么专用芯片值得造、教师模型怎样帮助学生模型、千人团队如何比较实验，也划出了能力演示与成熟方案之间的距离：一人管理几十乃至上百个
Agent
是研究方向，目标表达、交互方式、协作和奖励仍有问题待解。后半程对错误信息、工作转型和小规模研究的讨论，同样是这条主线的一部分。</p>

<a id="能力怎样从规模与学习目标中长出来00001223"></a>
<h2 id="foundations">能力怎样从规模与学习目标中长出来 <span class="picks-episode-time">（00:00–12:23）</span></h2>
<p><strong>规模和算法可以相乘，因为它们改善的是不同的东西。</strong>
Dean 举例，规模带来 20 倍改进，算法带来 50 倍改进，合起来就是 1000
倍：增加计算、数据和模型大小能提高能力；改进架构，则能让每次浮点运算学到更多。这些数字是关系示例，并非一个可以套到任意任务上的测量定律。他把过去十三四年持续出现的规模收益，与算法、软件和硬件的共同变化放在一起看。</p>
<p>1990 年还是本科生时，Dean 就试过用系里的 32
台计算机训练更大的神经网络。他研究的两种切分方式，对应今天所说的模型并行与数据并行。但加速曲线逐渐变平，因为他增加处理器时没有同时增加模型大小，固定的小任务越来越难继续拆分。他在台上自评“我做了件蠢事”（译）：这个早期反例已经说明，更多机器不会自动换来同比例收益。</p>
<p>后来在 Google，他与 Andrew Ng
的一次交谈促成了训练更大网络的尝试。团队构建分布式软件，训练了比他们能找到的既有最大模型大约
50–100
倍的网络。多个异步副本各自处理样本，计算梯度，再把更新交给参数服务器。代价是：一个副本算完梯度时，其他副本可能已改变参数。Dean
承认这在数学上并不严格，却在当时的实验中奏效。</p>
<p>其中一个实验使用 <strong>1000 万张随机 YouTube
帧</strong>，没有告诉模型哪张图里有猫或人。网络要从较高层的表示重建输入像素，瓶颈迫使它学会比原始像素更概括的表示。团队发现，一些高层神经元开始对猫脸、人脸或人体轮廓敏感。随后用这些无监督训练得到的权重初始化监督图像分类，Dean
报告在 <strong>ImageNet 22K</strong> 上相对当时最好水平提高了
<strong>70%</strong>。这里是 22,000 类版本，不是更常见的 1000
类版本；70% 也是相对提升，不是绝对准确率。</p>
<p>语言中的表示学习用了相似思路。一个并不深的模型，只用词的向量去预测邻近词，就能让
cat、puma、tiger 在空间中靠近，也能学到 king→queen 与 man→woman
这样的关系方向。再往后，序列到序列模型把一句英文编码成 LSTM
状态，从该状态逐词解码法语，通过平行句对提供监督。重要的是，训练目标可以让系统形成有用的表示，而不必由人逐项编写概念和规则。</p>
<a id="为什么要造-tpu还要重做互联12241925"></a>
<h2 id="tpu">为什么要造 TPU，还要重做互联 <span class="picks-episode-time">（12:24–19:25）</span></h2>
<p><strong>一个更好的语音模型，可能先变成无法承受的服务成本。</strong>
Dean
回忆，当时团队用相对朴素的八层全连接网络和大量数据，显著改进了语音识别。他做了一次粗略估算：如果让
<strong>10 亿用户每天对它说话 3 分钟</strong>，就需要把 Google
的计算机数量翻倍。这个容量问题促使团队认真投入专用芯片，而不是只继续扩大通用计算资源。</p>
<p>神经网络有两点适合专门优化。其一，尤其在推理中，可以接受约 7–8
位的低精度；其二，大量模型主要由矩阵乘法、点积、归一化和缩放等少数线性代数运算构成。一个不必运行浏览器或文字处理软件、专门执行低精度线性代数的加速器，因而能获得更高效率。第一代
TPU 约两年后出现；按 Dean 对当时 CPU、GPU 的比较，速度为 <strong>15–30
倍</strong>，能效为 <strong>30–80
倍</strong>。这些是所述硬件与测试背景下的结果。</p>
<p>训练还需要许多芯片一起工作。后续 TPU
因此成为带有定制高速互联的系统，在芯片间传输激活值、参数和梯度。v4
引入的光互联，可以让隔着约 100 米数据中心空间的两个 64
芯片机架，在网络拓扑上表现得像彼此相邻；一个机架坏了，还能换入另一架并重新连接。规模越大，故障越常见，重配置能力就越成为训练能力的一部分。</p>
<p>Dean 给出的尺度包括：TPU v4 单芯片峰值约 <strong>275
TFLOPS</strong>，一个 Pod 最多 <strong>4096 片</strong>；后续系统把 Pod
规模大致翻倍，并增加内存、带宽和计算能力。他还称 Ironwood 相对 TPU v2
的每 Pod 峰值性能约为 <strong>3600 倍</strong>、每瓦计算能力约为
<strong>30
倍</strong>。前一个指标同时包含整组系统规模的变化，不能读成单芯片提升
3600 倍。</p>
<p>共同的软件抽象同样关键。TensorFlow、PyTorch 和 JAX
让社区可以复用并改进同一批基础工具，研究者不必每次从机器通信重新开始。Dean
说，Gemini 的训练使用 JAX；这为后面的分布式系统抽象打下基础。</p>
<a id="transformer-与稀疏模型各省掉了什么19252707"></a>
<h2 id="architecture">Transformer 与稀疏模型各省掉了什么 <span class="picks-episode-time">（19:25–27:07）</span></h2>
<p>LSTM 的问题有两个，不能只归为“太慢”。处理一句 100
个词的话，它要更新状态 100
次；每次依赖上一次结果，这限制了现代硬件擅长的并行计算。同时，它还试图用一个状态向量保存此前所有可能有用的信息。Transformer
的关键变化，是保留各位置的表示，再通过可学习的注意力机制选择后来需要的部分。</p>
<p>在 Dean 展示的比较中，Transformer 用大约
<strong>十分之一的模型大小、十分之一到百分之一的计算量</strong>，就能达到较大的
LSTM 的相近质量。这个收益来自所示模型与测试损失的比较。将 Transformer
用于视觉后，他也展示了相对 ResNet-152 更低的 TPU
核心日消耗和更高的准确率，并指出注意力图能帮助观察分类时模型关注了图像哪里。</p>
<p>架构之外，文本本身提供了可扩大的学习信号：遮住一个词，让模型预测，再用原词计算误差。自回归目标只看左边，逐步预测下一个词；填空目标可以同时看左右两边，适合学习表示。两者都能利用大量文本，但正常对话生成时没有右侧尚未生成的内容，所以主要使用自回归模型。这里解释了为什么语言训练可以获得海量监督信号，也保留了两种目标适用场景的区别。</p>
<p>稀疏专家模型则解决另一个成本问题：<strong>并非每个输入都需要激活全部参数。</strong>
Dean
用担心垃圾车倒向自己的车时，不会同时调用思考莎士比亚诗歌的那部分能力作比喻。模型既学习不同专家，也学习该把当前输入送给谁；总容量可以很大，每次推理却只使用少量参数。</p>
<p>他给出两种取舍：在展示的实验中，达到相同准确率可以把训练计算降到约八分之一；也可以保持计算预算，训练质量更好的模型；实际选择还可以介于两者之间。这里的“八倍”是一个有条件的实验结果，真正可迁移的解释是容量与每次激活量不必同步增长。</p>
<a id="2-更强也要更可靠更便宜"></a>
<a id="训练没有宕机怎样知道它算对了27103323"></a>
<h2 id="reliability">训练没有宕机，怎样知道它算对了 <span class="picks-episode-time">（27:10–33:23）</span></h2>
<p>Pathways 希望让研究者把底层系统看作一台连接数万芯片的大计算机。Pod
内部用 TPU 专用互联，跨
Pod、跨楼和跨地域则使用不同网络；研究者主要表达机器学习计算，由系统处理通信与硬件替换。Dean
说，JAX 放在 Pathways 上，可以由一台主机上的一个 Python
进程驱动整场训练。</p>
<p>但机器、网卡或线缆不一定会明确报错。有时，它们受机架温度等动态条件影响，偶发地给出错误结果。同步训练会很快把这种错误传播开：梯度指数的一位翻转，就可能把
<strong>0.2 变成
10²⁰</strong>。因此，团队持续监测模型健康状况，其中一项是每一层的梯度范数。</p>
<p>看到尖峰以后，不能立即判定硬件坏了。Dean
紧接着展示了反例：某批正常样本本来就可能产生很大的梯度。团队会自动触发<strong>确定性重放</strong>，重新计算刚才的一步或几步；如果得到同样的结果，就倾向于认为这是数据造成的。如果重放结果不同，才有理由追查硬件。这个判断保留了他原话中的概率性质，并不构成绝对诊断。</p>
<p>另一个反例是，静默损坏也可能不产生明显尖峰。Dean
所举的这种情形对模型影响较轻，但仍说明监测不等于捕获全部错误。系统还会持续检查空闲芯片，维护热备资源；发现结果不一致并定位到相应
Pod
或芯片后，将坏件移出送修，用热备透明替换，让训练继续。这套机制把观察、重放、定位和换件连接起来，补上了“程序运行结束”与“计算值得信任”之间的一层。</p>
<a id="多想几步与向教师学习分别改变什么33253802"></a>
<h2 id="distillation">多想几步与向教师学习，分别改变什么 <span class="picks-episode-time">（33:25–38:02）</span></h2>
<p><strong>让模型生成中间步骤，是在推理时增加计算；蒸馏则把教师的能力转移给另一个模型。</strong>
Dean
先比较两种例题提示：一种只给出答案，模型照着直接回答下一题，却答错了；另一种给出完整解法，模型更可能照着分步求解，得到正确结果。每生成一个
token
都要再经过模型，因此较长的求解过程意味着更多推理计算。他报告，模型达到一定规模以后，思维链提示明显提高了
GSM8K 应用题的解答率；这既有模型规模条件，也不是“写得越长就越对”。</p>
<p>蒸馏利用的是另一种信息。面对“为……演奏协奏曲”的填空，训练样本可能只给出
violin 这个正确词。一个好的教师模型却能给出完整概率分布：piano、trumpet
也合理，airplane
则几乎不可能。学生因此学到各个候选的相对关系，而不只是这次有没有猜中
violin。Dean 认为，这在模型输出端提供了更丰富的梯度信号。</p>

<a id="强化学习的奖励从哪里来38034108"></a>
<h2 id="rewards">强化学习的奖励从哪里来 <span class="picks-episode-time">（38:03–41:08）</span></h2>
<p>预训练模型已有不少能力，强化学习可以进一步引导它怎样使用这些能力：回答的风格、长度、安全行为，以及面对复杂问题时采用的求解方式。Dean
把关键问题落在<strong>谁来告诉模型“这次更好”</strong>。</p>
<p>信号可以来自人：比较 A、B
两个回答，或判断一个回答是否合适；也可以来自另一个奖励模型，让它比较基础模型生成的候选。在数学和代码领域，还能使用可验证的结果：证明检查器是否接受证明，代码是否编译，编译以后是否通过单元测试，都能给出不同程度的奖励。</p>
<p>这些信号改善了数学、编程，也可能帮助邻近领域的推理与规划。但相应的边界是：没有清晰验证程序的任务，怎样得到足够有效的奖励？Dean
将它明确列为开放研究问题。因此，“能用模型给另一个模型评分”并不自动解决评价是否可靠的问题。</p>
<a id="投机解码为什么能更快而保持分布41094412"></a>
<h2 id="speculative">投机解码为什么能更快而保持分布 <span class="picks-episode-time">（41:09–44:12）</span></h2>
<p>自回归生成仍有一个串行瓶颈。输入的 1000 个 token
可以在预填充阶段并行处理，但生成回答时，后一个 token 要等待前一个 token
及其注意力状态。Dean 给出两个观察：大 Transformer
单步解码往往受内存带宽限制，搬运权重比算术能力更紧张；而不同 token
的难度差别很大。“七的平方根是……”这样的引导语比接下来具体的数值容易预测得多。</p>
<p>投机解码让一个快的小模型先起草若干
token，再让目标大模型并行检查。例如先起草 <strong>8 个
token</strong>，大模型一次检查这 8 个位置；如果平均接受其中 <strong>4.5
个</strong>，就能提高一次权重读取所服务的有效计算量。这是解释机制的数值例子，不是固定加速比。动画中，大模型接受的是按其自身概率分布判断可接受的草稿前缀。</p>
<p>Dean
强调，这种方法只改解码算法，不必重训或改变模型架构，并能保持<strong>与目标模型相同的输出分布</strong>。保证属于相应的概率采样算法，不能扩展为任意“小模型写、大模型审核”工作流的正确性保证；它也没有把目标模型本身变成不会答错的模型。</p>
<a id="3-通用能力走向具体产品"></a>
<a id="gemini-怎样汇合这些进展44125245"></a>
<h2 id="gemini">Gemini 怎样汇合这些进展 <span class="picks-episode-time">（44:12–52:45）</span></h2>
<p>Gemini 起初要解决的是资源和想法分散的问题。Dean 说，Google
内部有多个团队分别研究语言和多模态模型，分开投入计算、分开积累想法，不如集中到一个项目。他将启动时间记为
<strong>2023 年 2 月</strong>，参与者来自 Google DeepMind、Google
Research
等团队，目标是从一开始就训练多模态模型，再把它们用于广泛场景。</p>
<p>模型接触文字、音频、图像和视频，后来也加入少量激光雷达、机器人控制等数据，让它至少见过这些模态；输出端则逐步增加音频和视频解码器。输入输出可以混合、交错，而不只是把每种信息交给独立工具处理。TPU、模型并行与数据并行、跨数据中心训练、静默错误检测、Pathways、JAX、Transformer、稀疏模型、蒸馏、思维链、投机解码和强化学习，都在这里汇合。</p>
<p>为什么还要不断扩大上下文窗口？Dean 的对比很具体：万亿 token
的训练内容融合进数千亿参数以后，信息多少有些“混杂、模糊”（“muddled and
fuzzy”，译）；此刻给模型的 900 页材料则“很清晰”（“very
crisp”，译），因为它们还没有和别的信息混在一起。模型能够查看不同位置，摘取、概括和组合其中的内容。这是他对输入材料与参数中信息的区别所作的比喻，不是对准确引用或无误理解的保证。</p>
<p>不同尺寸的模型也让能力逐渐变得便宜。团队希望当代 Flash 尽量接近当代
Pro，同时超过上一代 Pro。Dean
说已经连续三四代维持这一趋势：今天较慢、较贵的能力，过一段时间可能进入更便宜的模型。他用“六个月后”说明当时的迭代体验，并没有给出未来每代都能兑现的承诺。</p>
<p>数学例子说明，进步还来自推理预算和通用性的变化。Dean
报告，模型在国际数学奥林匹克竞赛的六道题中解对
<strong>五道</strong>，达到金牌分数。此前的方案组合了
Lean、定理证明器和专门的几何模型；他这次介绍的方案则使用面向用户的通用
Pro
级模型，给予较高的推理时间预算。他强调它与几年前的小学应用题已有明显距离，同时明确说，还没有达到研究级数学。通用模型、较多计算和指定题集共同构成了这个结果的条件。</p>
<p>评测也不只有一道标准答案。Dean
介绍，用户可以向两个匿名模型提交同一个具体问题，再选择更喜欢的回答；大量两两比较累积成类似棋类排名的
Elo 分数。它反映的是这些问题和参与者评价中的相对表现。转载在此标注“百个
Agent”，恰好遮住了原本关于模型评价信号的讨论。</p>
<a id="从手写食谱到网站演示说明了什么52465900"></a>
<h2 id="demonstrations">从手写食谱到网站，演示说明了什么 <span class="picks-episode-time">（52:46–59:00）</span></h2>
<p>一对夫妇手里有英文和韩文的手写食谱。演示先让 Gemini
转录、翻译成两种语言，再要求用这些食谱制作双语网站，并加入自动生成的图片。Dean
由此提出一个判断：不具备编程技能的人，也能得到自己需要的软件形式的结果，世界上的软件可能因此更多。演示中他还请懂韩语的人判断翻译，不能把这个例子写成已经过语言质量验收的产品。</p>
<p>另一个演示把生物学材料变成可以拖动滑杆的交互可视化，使学习者通过调整参数理解材料。这里的变化是，模型不只给出一段解释，还能生成承载解释的界面。它展示了教育用途的可能性，但没有提供学习效果的对照实验。</p>
<p>图像部分也保留了具体动作：从建筑蓝图生成逼真的三维图像，给
Transformer
架构图添加解释；面对球和斜坡问题，按步骤生成球如何移动、最终落进 B
桶的图像。Dean
将后者类比于人解题时在脑中形成画面。生成出连续图解展示了一种解题表达方式，并不足以揭示模型内部是否按相同机制思考。</p>
<p>他还展示了为莱特飞机图添加数据标注，以及根据反馈给太阳系图加入冥王星和幽默说明。飞机图中的数字属于生成内容，演讲没有核验它们；较高质量的图像模型则需要更多计算。和食谱网站一样，这些例子说明“能做出的东西在增加”，没有单独测量长期维护、复杂存量代码集成，或一个团队使用工具后的净生产率。</p>
<a id="4-大团队靠共同基线迭代"></a>
<a id="千人团队怎样用共同基线迭代58186253"></a>
<h2 id="organization">千人团队怎样用共同基线迭代 <span class="picks-episode-time">（58:18–62:53）</span></h2>
<p><strong>先给大量探索留下空间，再让有价值的结果汇入可比较的共同基线。</strong>
Dean 用超过千人署名的 Gemini
报告说明组织规模：除了总体负责人、项目和产品管理，还需要模型预训练、后训练与强化学习、端侧版本，以及安全、视觉、音频、代码、Agent
和国际化等能力团队。</p>
<p>数据团队要回答，在有限训练 token
预算内怎样获得尽可能好的数据；评测团队要知道不同能力有没有进步；基础设施团队要让训练、服务和代码库运转。另有面向
Gemini N+2、N+3
的长期研究，等待合适时机汇入产品。不同工作有不同周期，需要共同的判断依据，而不只是更多讨论。</p>
<p>协作还受时区限制。Dean
说，约三分之一成员在湾区，三分之一在伦敦，其余散布各地；美西和欧洲每天大概只有三个小时适合同步交流。大量沟通因此必须异步进行。除了讨论群，团队使用
RFC
文档征求意见：有的只是一页早期想法，有的已比较十种变体，要求决定哪一种应进入下一代模型。他说当时已经有
<strong>5000 多份 RFC</strong>。</p>
<p>实验通过共同排行榜和基线进入决策。小规模实验可以做很多轮，只有有希望的方向才升级到中、大规模；隔一段时间，把已经在较大规模证实有效的改进合并成新的候选基线，再开始下一轮。共同基线使不同改动能够比较，也帮助团队判断哪些方向值得继续投入。最后的研究问答还补充了一个选择条件：不能只看小模型是否领先，还要看扩展趋势，见<a href="detail.md#research">资源有限的研究者应该比较什么</a>。</p>
<a id="5-多-agent-仍有关键开放题"></a>
<a id="多-agent-和巨大语料还有哪些开放题62076556"></a>
<h2 id="agents">多 Agent 和巨大语料还有哪些开放题 <span class="picks-episode-time">（62:07–65:56）</span></h2>
<p>Dean
设想，当前由一个人与聊天界面交互的方式，可能逐渐变成一个人委派十几个或上百个
Agent
做事。他随即加上一个关键条件：人通常只是粗略地描述自己想要什么，目标是“没有充分说清的”（“weakly
specified”，译）。因此，研究问题在于怎样设计管理五十个虚拟助手的人机交互方式，以及
Agent 怎样彼此合作完成任务。</p>
<p>这段没有展示一个已经验证的百 Agent 团队，也没有给出 Graph、Loop
或权限状态机的工程规范。联系前面的强化学习讨论，复杂协作还会遇到同一个难题：对不能直接验证对错的目标，怎样得到有效的反馈和奖励？原演讲给出的是值得研究的问题及其缘由。</p>
<p>上下文扩展也不是把所有内容塞进一次提示。Dean 说，百万 token
的窗口已经能容纳约千页文字或数小时视频，但如果能利用万亿 token
规模的语料，会更有价值。他设想用学习式检索先取回 <strong>3
万份文档</strong>，让轻量模型判断相关性，再把其中约 <strong>100
项真正重要的内容</strong>送进上下文，并通过预计算降低成本和延迟。这里的两个数量用于描述候选筛选过程，不是一套已经验证的固定配置。</p>
<p>他举的用途包括个人邮件、数据和照片，并明确附上“当然，要得到我的许可”（译）；还有网页与视频检索，以及让编码
Agent 利用整个 Google
代码库。重点在于把检索、筛选、上下文和预计算组合起来，让模型访问的知识范围大于单次窗口。</p>
<p>推理效率随之更重要。多个 Agent 不断调用模型、与其他同样在推理的 Agent
互动，需求会持续累积。Dean 将低延迟的差别说得很直接：<strong>100
毫秒响应与 5
秒响应</strong>，使用感受很不一样。他预计专为推理设计的硬件、模型与算法改进会继续重要，还看好用学习方法和强化学习自动化部分芯片设计；后一方向在这场演讲中没有展开。</p>
<a id="专业能力普及以后哪些风险仍要面对65126937"></a>
<h2 id="impacts">专业能力普及以后，哪些风险仍要面对 <span class="picks-episode-time">（65:12–69:37）</span></h2>
<p>Dean
对积极影响的判断是，更强的模型能把一些领域的深厚专业能力交到世界各地更多人手中。但他讲到的跨领域研究同时考察正面与负面影响：作者们围绕就业、教育、医疗、错误信息与媒体、治理和国家安全、科学等方向访问领域专家，再结合访谈与自己的判断形成报告。本段介绍的是他们如何扩大讨论范围；相关论文和网站没有作为本次阅读材料展开。</p>
<p>面对“最担心什么”的话题，Dean
先给出自己对安全争论的立场：他认为部分担忧被夸大了，审慎设计 AI
被允许执行哪些动作，可以支持安全部署。这是他的工程判断，并非演讲已经证明所有强大系统都能安全使用。</p>
<p>他接着具体指出两个近处的风险。第一，合成视频和音频可以逼真到连有经验的人、花很长时间检查也难以辨别，错误信息因此令人担心。第二，当系统开始完成此前做不到的工作，怎样让人做好职业转型准备、学会使用新工具，而不是在任务突然被自动化后失去应对能力？他对教育和生产率的乐观，始终带着“能否把转型做好”的条件。</p>
<a id="多生成几份答案能否减少幻觉70177149"></a>
<h2 id="hallucination">多生成几份答案，能否减少幻觉 <span class="picks-episode-time">（70:17–71:49）</span></h2>
<p><strong>更多候选加上比较筛选，可以降低一部分错误率，代价是更多推理计算。</strong>
Dean
在问答中描述的办法是：不要只生成一个答案，而是生成多个可能的求解过程，再让模型比较哪些完整答案、哪些局部片段更可能正确。他说，IMO
求解也使用了这一类方法，因为一个证明中的错误就会破坏整道题的解答。</p>
<p>他随即把话题拉回效率：如果每次最终回答之前，都先生成 <strong>16
份候选</strong>，再判断保留哪些、丢弃哪些，成本会明显增加。这是他举的计算预算例子。模型自评候选并不等于外部独立验证；他所主张的是减少幻觉，而不是消除幻觉。这也解释了为什么“让模型多想”和“让推理更便宜”需要一起进步。</p>
<a id="世界模型怎样进入模拟测试71047318"></a>
<h2 id="world-models">世界模型怎样进入模拟测试 <span class="picks-episode-time">（71:04–73:18）</span></h2>
<p>现场问题把 LLM 与正在出现的世界模型放在一起比较。Dean
先把世界模型解释为：理解多种模态，以及世界在物理层面怎样运作；再提出他认为
Gemini 已经具备一些相应能力。他用下面两个例子说明自己的判断。</p>
<p>他举 Genie 3 为例：它建立在 Gemini
模型之上，可以根据文字生成想象世界，让人向左、向右、前后移动或跳跃，并保持环境的一致性。向左转再转回来，原来存在的东西还应在那里。这种持续交互中的一致性，是他强调的能力。</p>
<p>与 Waymo
合作的模拟案例则给出用途：让模型生成“<strong>一头大象出现在道路中央</strong>”的场景，构造现实中很难遇到的几十个长尾测试案例，观察车辆如何应对；系统还可以合成对应的激光雷达数据。Dean
将它作为改进安全测试的工具。生成这些场景扩大了可测试的情况，并不等于仅凭模拟就证明现实驾驶已经安全。</p>

<h2 id="research">资源有限的研究者应该比较什么 <span class="picks-episode-time">（73:23–75:24）</span></h2>
<p><strong>先证明一种新想法具有值得继续扩大的趋势，不必一开始就争取最好成绩。</strong>
Dean
对小规模研究的回答，补充了前面大团队筛选实验的方法：持续学习、新模型架构等方向，都可以从很小的实验开始，不必先拥有上千块加速器。</p>
<p>团队会比较“极极小、极小、小”等几档规模。新想法在最小规模可能低于当前基线，但如果随着规模增加，趋势更好，就值得继续看；反过来，即便一开始领先，稍微扩大便迅速落到基线以下，也不那么有吸引力。单个点的位置与扩展的斜率给出的是不同信息，这种观察是筛选研究方向的方法，不能当成无限扩展一定成功的保证。</p>
