<h2 id="摘要">摘要</h2>
<p>团队按要求交付了功能，甚至可能拿到了奖金，为什么整个产品反而更难用了？Tobi
Lütke 回忆，疫情期间重查 Shopify
路线图，他发现有团队为进入超市市场做出了一套功能，单看项目交付很成功，接入整体却成了孤岛。他每天花十六小时逐项清查，取消了“可能六成”的项目。这次危机让他重新拿起工程师的工作方式：检查前提、比较解法、让选择的代价显现，再设计公司下一次怎样作决定。</p>
<p>这套做法同时包含建模与判断。Shopify OS
把职级、薪酬和人员配置放进可计算的约束；项目评审让团队在阶段内探索，到增加资源或准备发布时重新确认责任；内部播客保存决定当时的条件。他又警惕把品味变成可供表演的清单，把好方法复制成失去原理的外观。后半场从上市、招聘和办公室一路谈到游戏与
Agent，始终追问同一件事：怎样让人掌握自己的工作，在反馈中提高，又让局部努力真正组成一家公司？</p>

<h2 id="company-as-experiment">1. 公司让一种设想接受检验 <span class="picks-episode-time">（00:00:02–00:05:27）</span></h2>
<p>公司让一个人可以长期钻研“世界上应该有、现在却没有”的东西，也让其他人能够加入。Tobi
称它是一种社会技术：同样是每天投入许多小时，叫作一家公司的工作，就获得了可以持续做下去的组织形式。设想仍须接受市场检验；顾客愿意付钱，资源便流回来，使试验能够继续。他说，自己起初没预见到那么大的市场，是市场从原先的项目中“拉出了”Shopify。</p>
<p>这种理解也把公司制度变成可改进的对象。今天看似自然的职位、组织和管理方式，也只是历史选择积累出的结果。主持人
David Senra 提到，Tobi 曾说包括 Shopify
在内，公司都还有很多糟糕之处，未来回看可能令人难为情。Tobi
用程序员重读旧代码回答：今天能看出过去过度抽象、过度复杂的地方，差距就是进步。</p>
<p>他最难受的一次，反而是发现旧代码写得很好。David
追问，是因为这意味着自己没有继续进步吗？他承认如此：那段时间忙于建公司，没有整天编程。承认旧成果不够好，在这里是一种继续学习的能力；并不意味着所有已有制度都应立刻推翻。</p>
<a id="2-读书也要识别作者的镜头000527000754"></a>
<a id="2-读书也要识别作者的镜头05270754"></a>
<a id="section-02"></a>
<h2 id="reading-and-ceo-imitation">2. 读书也要识别作者的镜头 <span class="picks-episode-time">（00:05:27–00:07:54）</span></h2>
<p>几小时阅读可以借用别人一生的经验，这是 Tobi
看重书的理由。他建议先养成习惯，大约每读三本就换一种类型，扩大可调用的视角。不过，阅读还要辨认作者用什么镜头看世界：销售出身的人容易把问题归结为销售，营销出身的人则容易找到营销答案。</p>
<p>为了避免同样的偏见，他曾刻意不把一切当成工程问题。上市后，他试着成为想象中“严肃的上市公司
CEO”：划分业务线，把事情交给经理人，靠定期汇报掌握进展。事后他用很重的话说，这几乎毁了公司，反而是疫情救了它。</p>
<p>因此，这段经历没有否定阅读和授权。它暴露的是另一种误判：发现自己的专业视角有局限之后，便用一个想象中的
CEO 模板替换它，却没有确认那套安排是否适合眼前的产品。</p>
<a id="3-对手可以提升标准也可以带偏方向000754001056"></a>
<a id="3-对手可以提升标准也可以带偏方向07541200"></a>
<a id="section-03"></a>
<h2 id="rivals-and-initiative">3. 对手可以提升标准，也可以带偏方向 <span class="picks-episode-time">（00:07:54–00:10:56）</span></h2>
<p>盯着对手做了什么，很容易把公司变成响应机器。Tobi
举例，有些公司的竞争分析频道是最活跃的 Slack
频道；每看到一个新功能，就想补上自己的版本。竞争情报有用，但这种习惯会挤掉自己的方向。临摹一幅名画，也不代表下一幅作品就能达到同样水准。</p>
<p>他更喜欢把同行当成提高自己的参照。谈到 Agassi 与
Sampras，两人指出，Agassi 心中的那个对手，与 Sampras
在自己传记里呈现的样子并不相同：一个厌恶网球，一个单纯喜欢网球，但前者构造的竞争关系仍推动了他。Michael
Jordan
可能想象过某次冒犯的故事，也用来说明竞争的心理作用。这里的体育轶事是谈话中的类比。</p>
<p>主动性也可以体现在没有人要求时抓住机会。David 谈到 Dr. Dre 与 Jimmy
Iovine 的纪录片，Tobi 接着说，嘻哈是最早在 Shopify
上表现突出的音乐类别之一：他们把文化、需求和新渠道迅速变成产品。平台让他近距离看到，不同行业吸收新想法、采取行动的速度可以相差很大。</p>
<a id="4-一个项目做对了整体仍可能做错001056001602"></a>
<a id="4-一个项目做对了整体仍可能做错约12001602"></a>
<a id="section-04"></a>
<h2 id="roadmap-and-composability">4. 一个项目做对了，整体仍可能做错 <span class="picks-episode-time">（00:10:56–00:16:02）</span></h2>
<p>Tobi 回到自己扮演“成熟
CEO”的经历时，先补上一项区分：经营表现一路尚可，真正失灵的是产品方向。疫情推翻了一项此前几乎没人写出来的假设：人可以自由出门。他把计划看成一棵从前提不断推导的决策树；某个上游变量失效，应该退回那里重新推导后面的选择，不能只在原路线图末端修补。</p>
<p>实际清查比他想象得难。当时公司约四五千人，分布在渥太华、多伦多、蒙特利尔等地，拿到完整路线图都遇到阻力。多伦多有个不小的项目，要增加让
Shopify 能经营超市的功能，理由是行业很大，拿到 <strong>1%</strong>
就值得做。他没有断言进入超市必然错误；问题是团队找到一个说得通的答案，就停止寻找别的答案。</p>
<p>在工程中，几个答案都可能完成目标，但工作量和组合能力大不相同。好的组件加入之后能与其他部分一起工作；差的解法需要不断补胶水代码。超市项目按自己的简报看可能表现出色，团队或许也拿到了奖金，交付物却是一座岛，其他产品部分无法自然与它配合。项目成功与产品成功由此分离。</p>
<p>他也承认自己的管理方式参与制造了盲区：看见负责人有热情、有把握，就信任对方会作对决定，之后只接收更新。人们很快学会他对哪些项目感兴趣，于是多讲那些、少讲其他。汇报仍在进行，注意力却已经被筛选过。</p>
<a id="5-危机重建了他的团队观001602002336"></a>
<a id="5-危机重建了他的团队观16022336"></a>
<a id="section-05"></a>
<h2 id="crisis-and-founder-team">5. 危机重建了他的团队观 <span class="picks-episode-time">（00:16:02–00:23:36）</span></h2>
<p>Tobi
回忆，自己用每天十六小时逐项审查的方式，取消了“可能六成”的项目，并在一年内更换了所有高管。这些数字是他的回顾。他紧接着补充，不愿对原团队作不公平评价，但许多关系中的信任确实被破坏了。</p>
<p>危机也推翻了他对人的预判。他用夸张的刻度形容：原本都像“一”的人，有人变成零，有人变成一百；若事先押谁贡献最大，自己可能全押错。David
问为什么，他先承认没有找到好解释，甚至当事人事前也未必知道。随后，他才提出事后发现的线索：那些曾经创办公司、为别人生计负责的人，往往能迅速适应。</p>
<p>公司收购来的创始人一直有个 Slack
频道，他便向那里求助，请其中一些人加入高管团队；还有人直接从工程个人贡献者岗位转去负责很大的业务。按他的说法，这些尝试都奏效了。承担过一家公司的经历，让他们能够理解问题的分量，也不愿因为别人已经同意往前走，就闭口不谈明显缺陷。</p>
<p>同一种特质此前却令他们成为组织里的“麻烦”。Tobi
说，公司容易把这样的人包裹起来，放到边缘创新组，仿佛办了一个“创始人托儿所”（译意）。他这次把他们放回决策中心，也重新承认自己十五年积累的直觉可能有价值。</p>
<p>“相信直觉”仍有条件。David
随即指出，十五年后的直觉与刚创业时不同；Tobi
也说，没有人天生具备建公司的直觉。Larry Ellison
曾因销售激励吃大亏的故事让他很有共鸣，因为自己也经历过同类问题。成熟经验并不消除盲区，别人的传记仍可能让人少交一次学费。</p>
<a id="6-shopify-os让隐含选择显形002517003252"></a>
<a id="6-shopify-os让隐含选择显形2517约3300"></a>
<a id="section-06"></a>
<h2 id="shopify-os">6. Shopify OS：让隐含选择显形 <span class="picks-episode-time">（00:25:17–00:32:52）</span></h2>
<p>把公司作为工程项目来做，第一步是把输入写清楚。Tobi 建了一个 GitHub
项目，将职位、职级、经理应带多少人，以及市场薪酬等资料放进配置；原来是
PDF 的数据先变成机器可读文件。他用 Python 和 SAT
求解器，在给定约束下计算组织可能的样子，后来又有两三个人加入。这就是
Shopify OS 的起点。</p>
<p>第一版结果完全不对，却暴露出更基础的问题：公司还没有统一决定那些原则。他回忆，约
<strong>8,000 人有 5,500 种职位名称</strong>，某些部门的 senior staff
高于
director，另一些部门正好相反。原本分散在不同团队里的矛盾，一旦要求软件能够表示、重新计算，就显了形。</p>
<p>模型最直接的价值，是让一个决定的另一面同时出现。销售负责人要增加五十人，可以先放进系统，看到按既定预算和规则，是否需要调整别处，或减少工程师。增加销售也许是正确选择；但不能只在打高尔夫时答应招聘，随后让工程团队在不知不觉中失去创新资源。</p>
<p>他借“期望状态系统”描述后续工作：计算希望达到的状态，对照现实，再寻找从这里到那里的迁移步骤。HR
负责协调这种变化；如果模型没表达真实目标，也要改模型。计算使假设可讨论，没有替人决定什么组织最好。</p>
<p>对职业发展的重审也从这里展开。为了获得更好收入，优秀工程师可能被推去管理，虽然他们未必喜欢或擅长管理；他发现，招回好工程师的地方就在自己的管理团队里。于是公司把
mastery
通道扩展到各种工作，让人在原有职责上练得更好，也能升级、增加报酬。个人贡献者收入超过经理或副总裁是可能的，前提仍是创造的价值。</p>
<a id="7-股价下跌揭示了选择权问题003252003951"></a>
<a id="7-股价下跌揭示了选择权问题约33004041"></a>
<a id="section-07"></a>
<h2 id="flex-comp-and-agency">7. 股价下跌揭示了选择权问题 <span class="picks-episode-time">（00:32:52–00:39:51）</span></h2>
<p>股价下跌约 80%，Tobi 为什么反而感到释然？David
追问后，他才给出条件：当时不急着融资，账上有钱，债务少，内部单位经济表现很好；高点估值则可能已经超过年收入的五十倍。他明确说记不清准确数字，连相关年份也有些混淆。对他而言，股价像市场对未来价值的下注，而自己的任务是把实际业务做好；高报价还会带来必须追上的期待。</p>
<p>员工的处境并不因此轻松。高位获得的期权可能多年都处于水下，要付出很大努力才回到开始值钱的位置。Tobi
复述员工的理由：股票是公司发来的，自己被动接受，因此公司应承担补足的责任。他没有全盘同意这个结论，因为风险本来就存在，报价也不是自己设定的；但他接受了其中一个关键点——员工没有参与选择。</p>
<p>Flex Comp
因而围绕选择权重做。在公司给定的年度总报酬内，员工用滑块调整现金、RSU、期权等配置，并可以每季度重新选择。他说，员工也可以主动选出与传统公司相似的期权安排；原则是自己知道并决定如何配置。持有的股票上涨，可能获得增益；价格下跌，下一季度则按当时价值重新平衡，获得相应更多的期权。</p>
<p>他还提到锁定所获股票三年价值的工具，以及 Shop Cash
选项。这些属于嘉宾的制度描述，具体适用范围受前述来源边界约束，不能由此推成无风险薪酬。跨国家实施也并不简单：各地关于改变薪资的规则，让这项改造成为一场复杂的法律协调工作。</p>
<p>David
随后确认先后顺序：组织工程项目已经开始，后来才遇到股价变化。Tobi
说前者大概在 2021
年初，同时承认那些没有周末、持续工作的年份在记忆里混在一起。这也解释了他为什么看重记录：后来要重建历史，不能只靠对一段时期的整体印象。</p>

<h2 id="identity-and-future-notes">8. 给自己建立有用的身份 <span class="picks-episode-time">（00:39:51–00:47:40）</span></h2>
<p>每位高管都要能公开讲清楚：本部门在 Shopify
有什么不同，为什么更好。Tobi
要求他们每年在播客或会议上做这件事；若还讲不清，就一起把想法理顺。他认为，公开解释既逼人厘清方法，也把“我要这样做”变成一种自己愿意履行的承诺。</p>
<p>这与他的自我训练相连。他曾害怕公开演讲，于是一周里每天花约十分钟，反复写自己喜欢演讲，后来感到恐惧减轻。David
惊讶于一个工程师如此相信肯定语，Tobi
则把自己描述为看重结果的工具制作者。他关于大脑、额叶变化及“不是安慰剂”的解释，在这份访谈里没有实验支持，应读作个人理解。被问到可视化或显化时，他的回答也更弱：也许有用，关键是什么方法有效而且快。</p>
<p>另一个办法更具体：给未来的自己发定时消息。年度公司峰会演讲结束后，趁记忆还鲜明，记录准备过程中哪里好、哪里不好、下次应改什么，以及被删掉的题目。等下一轮准备时再读，反思便会在用得上的时候回来。他把这当成对重要想法的间隔复习。</p>
<p>他对工作的定位也依赖这种持续整理。自己关心的是帮助商家借助技术实现想法；AI
出现，并不自动意味着必须换去一家 AI
实验室。在变化的环境里重新解决已经关心多年的问题，对他很有吸引力。公开承诺、未来留言与职业身份，都在帮助他把日常行动接回这个方向。</p>

<h2 id="difference-and-iteration">9. 差异的价值在于掌握迭代 <span class="picks-episode-time">（00:47:40–00:50:31）</span></h2>
<p>“做得不同，即使起初更差”，为什么有时值得？David 从 Dyson
的经历引出这个主张，Tobi
给出自己的机制：复制一个市场上的七分方案，很快也能做出七分；从原理搭自己的六分版本，却可能真正掌握它，知道怎样改到七分以上。</p>
<p>这里有价值的不是差异本身，而是继续改进的能力。理解了哪些东西昂贵、哪些不必要，团队就能调整和删减；只复制成品外观，很难知道下一步怎么走。David
同时引用 Edwin Land
不愿做别人也能做的东西，并保留了那句座右铭原有的限定：这是个人做法，未必适合别人。</p>
<p>Tobi 尤其喜欢 Raptor
火箭发动机演进的图片，因为它在他看来呈现了团队通过减法推进复杂工程的能力。他把它当成这个时代的杰作。这是他对工程的审美判断，不是由图片独立证明的技术结论；六分与七分的比喻也不能免除具体产品应满足的要求。</p>
<a id="10-保存决定的条件别只保存结论005031005439"></a>

<a id="section-10"></a>
<h2 id="context-and-decisions">10. 保存决定的条件，别只保存结论 <span class="picks-episode-time">（00:50:31–00:54:39）</span></h2>
<p>“Tobi
说过”在公司里很容易变成一句封口令。他希望大家追问的是：“什么时候？”（译引，原文为
“When?”）有时团队选了明显更麻烦的办法，追查之后才发现，是在沿用别人转述的旧要求；而那个要求当时的条件，早已不在。</p>
<p>内部播客 Context
因此记录重大决定周围的信息：为什么在那时这样选，知道什么，如何理解问题。David
提到 Spotify
的产品历史节目，也强调由当时作决定的人解释从桌面到移动等转变，比外部事后替他们拼故事更有价值。保存背景，让后来者理解和重审决定，而不是只继承结论。</p>
<p>节目形式同样可以改。Tobi 回忆，最初大约五十期压在 <strong>23
分钟</strong>，因为他们计算员工住处与办公室之间的平均通勤时间，得到了这个数，而不是凭感觉选二十分钟。后来发现听众可以暂停、跳转，主题有时需要讲得更长，便取消限制。一次与杰出工程师讨论工程哲学的谈话长约五小时，拆成了几期。约束有理由，理由变化后也就可以调整。</p>
<a id="11-软件浪费常由别人付账005439005857"></a>

<a id="section-11"></a>
<h2 id="software-cost-and-users">11. 软件浪费常由别人付账 <span class="picks-episode-time">（00:54:39–00:58:57）</span></h2>
<p>软件的低复制成本既带来好生意，也使低效不容易显形。Tobi
对比硬件：材料清单、生产缺陷、元件发热都会形成明确代价，工程师必须持续计算浪费。软件却能把大量机器性能消耗掉，等规模够大、成本明显时，往往是运维购买更多服务器，而不是原来的团队返回去改设计。他把这种后果没有回到决策者身上的现象，比作污染的外部成本。</p>
<p>电商尤其容易暴露它。顾客可能很少来，同一个站点的第一次访问需要重新加载全部资源；工程团队在最新
MacBook、充足内存和良好网络下看到的演示，并不是买家得到的体验。Tobi
描述普通 Android
手机上的乘客，坐在火车里等了一分半钟，商店还没打开。David
接话说，这样的转化率会是零。这里是情境说明，不是一组实测转化数据。</p>
<p>更尖锐的反例是，Tobi 称有客户为自建技术栈招来 CTO
和团队，采用当时最流行、会议也最吸引人的技术，最后业务因此失败。新技术在演示中可行，不能替代首次加载、设备和网络条件的检验。技术选择产生的负担，最终可能落在顾客和商家身上。</p>
<p>他把这类问题与 2023
年的经历联系起来，也观察到零利率环境结束后，团队突然更少容忍技术栈里的浪费。他并未确定内部那次工程讨论究竟起了多大作用，甚至觉得是外部环境改变了行为；这是一种因果观察，访谈没有提供可分离这些影响的数据。</p>
<a id="12-把好方法传播出去仍留出探索空间005857010100"></a>

<a id="section-12"></a>
<h2 id="spread-methods-keep-exploring">12. 把好方法传播出去，仍留出探索空间 <span class="picks-episode-time">（00:58:57–01:01:00）</span></h2>
<p>把好方法分享给所有人，不一定要立刻要求所有人照做。David 讲述 Kinko’s
创始人 Paul
巡店的办法：各店有不同经营者，试验很多；他发现好点子后，打进公司语音信箱，留下约三分钟更新，员工第二天来就能听到。</p>
<p>被问到为什么不把某家店的最好方法强制推广，Paul
的回答是，那样它可能就成为永远最好的方法，因为探索停了。这段故事呼应了前面的多种解法：发现一个好答案，未必已经穷尽其他可能。</p>
<p>Tobi
接着提出，告诉团队每一步怎么做，大概能得到自己想象中的结果；不预先规定动作，则可能得到自己根本想不到的解。他明确加上了“如果有好的人”这个前提。领导的工作因此落在环境、问题和人上：使能力可以发挥，留出探索空间，而不是只把自己的动作复制给所有人。</p>
<a id="13-阶段转换承接自治与责任010100010723"></a>
<a id="13-阶段转换承接自治与责任约61006723"></a>
<a id="section-13"></a>
<h2 id="phase-transitions">13. 阶段转换承接自治与责任 <span class="picks-episode-time">（01:01:00–01:07:23）</span></h2>
<p>流程通常用于防止人做错事，却可能同时压低最强的人能做到的上限。Tobi
更愿意先问，为什么直觉会把人引向错误？能否改变环境，让正确行动更自然？能否找来判断经过更充分训练的人？他把过度规定动作叫作公司里的“防婴儿磕碰措施”，但实际做法仍保留了清晰的项目评审。</p>
<p>探索阶段像一个尚未照亮的房间。以 Agent
参与购物为例，团队要弄清怎样提供商家的商品目录、怎样完成交易、模型要知道什么才能做好个人购物助手。他可以画出方向，帮助团队喜欢上这个问题，配置所需技能，明确谁能作哪些决定；进入房间后，具体探索仍由团队完成。公司每天有大量决定，不可能都由他控制。</p>
<p>学习到足以提出可建设的方案时，团队申请离开原型阶段。它要说明准备做什么、学到了什么，经过一次实际会议，获得工程、设计负责人以及
Tobi 相应层次的同意，才进入建设阶段。团队可以先用基于他过往评审训练的 AI
预演，看看哪些地方可能受质疑；预演节省准备和审阅时间，正式决定仍由人承担。</p>
<p>转段同时转移风险。他说，人只愿意承担一定程度的不确定性，团队需要知道何时可以把更大的风险交给负责人或公司。管理者承接责任，团队则在新阶段重新获得自主决定的空间。增加人手、准备发布等节点再评审，也可能得到“还没准备好，需要改”的回答。</p>
<p>这套机制来自疫情时的教训：当时连弄清所有项目都很困难，下一次就应该更快看懂，并能作资源配置决定。阶段内的自由、阶段间的评审和公司层面的可见性，共同使自治有了可持续的安排。</p>

<a id="section-14"></a>
<h2 id="past-work-and-stewardship">14. 重新看待旧成果 <span class="picks-episode-time">（01:07:23–01:15:10）</span></h2>
<p>假想自己刚廉价收购了一家破产公司，是 Tobi 每年重看 Shopify
的方法。以新管理者身份进门，原有决定就不会仅因为“是我做的”而值得保留。他还会写文章，专门列出自己引以为傲的系统有哪些毛病，用这种距离克服沉没成本。</p>
<p>可一旦公开批评旧成果，接收者未必感到兴奋。Tobi
说，他需要让别人明白自己并非在评判他们过去的工作。David
当场纠正：你确实在评判作品，只是没有评判他们作为一个人。Tobi
接着解释，关键是贡献被接纳之后，就进入公司的公共成果；作者值得记功，但成果不再是不可触碰的私人领地。</p>
<p>代码合并、项目获准之后，其他人随时可以继续改进。公司因此更像共同维护的开源项目。他用
stewardship，也就是照管责任，替代对代码一部分的
ownership。照管者有职责维护质量，却不因最初写了它就获得排他的处置权。</p>
<p>David 用 Dyson
不断拿起产品、寻找改进点的故事追问，这种看见问题的习惯会不会变成苛刻的自我折磨？Tobi
回答，自己反而兴奋：公司已经运行得不错，又发现一个薄弱处，就相当于拿到下一步变好的清楚路线。他承认，有时用嘲弄现状来激发改变，会在接收者心态合适时奏效，也可能完全不受欢迎。区分作品和人，并不能自动消除表达造成的伤害。</p>
<a id="15-改变建议的入口011510011732"></a>
<a id="15-改变建议的入口约75107732"></a>
<a id="section-15"></a>
<h2 id="feedback-as-shared-work">15. 改变建议的入口 <span class="picks-episode-time">（01:15:10–01:17:32）</span></h2>
<p>方案有问题，立刻走到白板前重写架构，技术上可能帮了忙，交流上却可能失败。Tobi
仍会参与新项目，有些内部仓库最初二三十个提交来自他；看见自己做过的问题，很自然就想直接画出更好的解。</p>
<p>联合创始人 Daniel
提醒他，对方拿来展示的通常是当时最好的作品，也很在意他的评价。即使他确实当场画出了更好系统，对方仍可能先进入防御，急着挽回面子。技术论证越正确，也不保证对方越容易听进去。</p>
<p>Daniel 建议换一个入口。Tobi
试着先说，还有几种办法值得考虑，然后提出：“比如，这样怎么样？”（译引，原文为
“For example, what about
this?”）架构意见可以完全一样，关系却变成双方一起解决同一个问题。他强调有效的并非某五个词本身，而是把建议表述为共同探索的输入。</p>
<a id="16-离开中心也能学习中心011927012636"></a>
<a id="16-离开中心也能学习中心79278636"></a>
<a id="section-16"></a>
<h2 id="ottawa-and-own-rules">16. 离开中心，也能学习中心 <span class="picks-episode-time">（01:19:27–01:26:36）</span></h2>
<p>在渥太华创业，让 Shopify
少一些人员在相近公司间频繁流动带来的趋同。Tobi
认为，在硅谷做一套很不同的公司，往往先要纠正新人从别处带来的预期；留在外面，则更容易形成自己的解释方式。</p>
<p>早期他仍每年去硅谷几次，尽量吸收经验，回去再翻译成适合 Shopify
的办法。多年后才意识到，自己拿来比较的并不对称：一边是自家平常的状态，一边是别人想达到的愿景和最光鲜的片段。它有时意外抬高了目标，但不能说明对方真实运作就像讲述中那么好。</p>
<p>上市时的高管团队，只有一个人曾在上市公司工作，没有人带过
IPO，也没有人当过上市公司高管。他们给自己的说法是，创造一个“上市版本的
Shopify”（译意）。具体到路演，遵守必要的信息与监管约束之后，他们发现没有规则要求
CEO
对着摄像机逐页讲幻灯片，于是拍了讲述公司来历和目的的纪录片，目标是让观众在前二十秒就愿意全屏看下去。</p>
<p>对规则的这种敏感，也出现在薪酬漏洞上。David
提到有人研究制度后找到赚更多钱的办法，Tobi
承认不会轻易责怪在既有激励下作聪明选择的人：若制度奖励了偏离公司目标的行为，设计者要负责。但他紧接着加上条件，之后怎么做很重要；不断利用弱点，与发现问题并及时提醒团队，是不同的事。双方仍在同一个团队里，他希望员工把漏洞告诉自己。</p>
<a id="17-上市决策要比较两边的代价012636013429"></a>
<a id="17-上市决策要比较两边的代价86369508"></a>
<a id="section-17"></a>
<h2 id="ipo-and-status-quo">17. 上市决策要比较两边的代价 <span class="picks-episode-time">（01:26:36–01:34:29）</span></h2>
<p>反对上市的理由存在，并不意味着维持私有就没有代价。Tobi 说，2013、2014
年讨论这件事时，公司只有约八百人，又在加拿大，朋友普遍劝他再等一等。Shopify
最终在 2015
年上市；他回忆最初交易时的估值约十亿至十五亿美元，而不是后来成熟企业的体量。</p>
<p>他有一项明确的价值判断：公开市场也应该有成长机会。若公司一直留在私有市场，更多增长收益就只对机构和已经富有的投资者开放；较早上市，让普通投资者也有机会参与。这是他支持公开市场的理由，并不是对投资回报的承诺。他对治理又有不同偏好，认为拥有更多情境知识的人应作决定，并将这一点同时用于领导和一线团队；谈话没有系统解决股东治理的全部争议。</p>
<p>David 追问，当年的反对意见是否只是大家模仿彼此？Tobi
没有顺着这个判断走，而是先说那些人通常有道理。他反对的是一种评估方式：只要有人说出新方案的一个缺点，就让整个方案出局，却不把现状的缺点同样列出来。熟悉的选择有已知利弊，新选择的上行空间可能还不清楚，缺点反而容易表达，于是默认不动。</p>
<p>对于一家向美国企业销售电商平台的加拿大小公司，私有身份和有限知名度会影响信任。把上市带来的品牌传播、人才吸引力、股票流动性放在同一张账里，他觉得收益明显更大。向外部解释业务也逼他加深理解；对他而言，定期电话等负担没有压过这些价值。</p>
<p>David
又补充其他创始人的用途：上市股票可以成为并购的支付手段；定期公开结果，也让别人有机会指出“你说要做的事”和实际表现之间的距离。它们使比较更完整，但并不导向所有公司都应尽早上市。Tobi
的方法是把两条路的代价、概率和潜在收益对称摆开。</p>
<a id="18-先让公司值得被选择013429014150"></a>
<a id="18-先让公司值得被选择950810150"></a>
<a id="section-18"></a>
<h2 id="company-worth-joining">18. 先让公司值得被选择 <span class="picks-episode-time">（01:34:29–01:41:50）</span></h2>
<p>管理者能控制的是公司是否值得优秀人才来工作，不能直接控制人才是否喜欢它。Tobi
从“职责分开”的思路出发：如同人应该让自己值得被喜欢，而不是要求别人喜欢，公司也要先减少政治和无意义的消耗，给人重要问题、资源和真实影响。</p>
<p>他想让大公司保留小公司的感受，同时拥有大量资源，能把产品交给数百万自己尊重的用户。早期他估计需要约一千名同道，在北美东部聚集这样的人，比进入硅谷参与最高薪酬竞争更符合这个目标。反过来，十年后造出一家连自己都不想工作的公司，对他才是真正可怕的结果。</p>
<p>他把员工也视为经营自己能力的人：产品是能完成的工作，市场是可供选择的公司，就业像双方自愿订立的一份独家订阅。要求更多报酬，也需要说明能为共同项目增加什么贡献。他明确限定，这里谈的是拥有稀缺技能、强烈驱动力和许多选择的人，并没有把这种自由程度泛化给所有劳动者。</p>
<p>“把公司做好，人才会来”随即得到他自己的修正：信息有缺口，声誉有滞后，自己仍花很多时间招聘、向外界解释。Shopify
要求专注和投入，也不争做市场最高报价者；他更愿意承诺在优秀同伴、文化和任务要求下更快成长。这是他的招聘主张，不能读成每个人已被验证的职业收益。</p>
<a id="19-看看人在困难时做了什么014150014737"></a>
<a id="19-看看人在困难时做了什么1015010828"></a>
<a id="section-19"></a>
<h2 id="hiring-and-scarcity">19. 看看人在困难时做了什么 <span class="picks-episode-time">（01:41:50–01:47:37）</span></h2>
<p>招聘时，Tobi 想找到的是有突出能力、也会主动行动的人。David
用“有尖峰”的人才形容这种偏好，并讲到 Steve Jobs 早年在 Atari
与环境格格不入的故事。Tobi
认同不应只找履历平滑的人，但他实际描述的筛选方法落在经历与手艺上。</p>
<p>面试者讲自己的人生故事，讲到某件事出了问题，就把镜头拉近：接下来每一分钟怎样判断、做了什么？这样可以辨认主动性，也要确认对方能实际做出出色工作，而不只是会谈论优秀。团队里有些人先做
Shopify
商家，再申请加入；与敬佩且能相互学习的人共事，是公司能提供给员工的重要价值。</p>
<p>这种取向也受早期资源约束塑造。他回忆，自己约四年没领薪，住在岳父母家，在妻子
Fiona
原来的卧室里加一张宜家桌子开发产品，岳父曾在发不出工资时帮忙。让每一美元有用，是不得不养成的习惯。他担心很大的早期融资会放大原来的用钱方式；钱多了，不会自动使不谨慎的人变谨慎。</p>
<p>David
举了一位年轻创始人展示豪华办公室照片的反例，追问这怎样改善顾客得到的产品。对方说办公室漂亮能吸引人才，他并不满意。但
Tobi
没把这个例子推成“办公室不重要”：他反而觉得很多公司长期低估了空间，只是好的空间不必昂贵。问题由花不花钱，转向钱怎样改善工作。</p>
<a id="20-空间应该帮助人自然地工作014737015714"></a>
<a id="20-空间应该帮助人自然地工作1082811714"></a>
<a id="section-20"></a>
<h2 id="office-as-designed-environment">20. 空间应该帮助人自然地工作 <span class="picks-episode-time">（01:47:37–01:57:14）</span></h2>
<p>给定最高预算、使用并不顶级的办公空间，仍然可以设计一个适合出色工作的地方。Tobi
把这项工作交给联合创始人 Daniel Weinand，约从 2010
年的第一批办公室开始试。Daniel 不接受开放办公与独立房间的二选一，而是从
Shopify 要怎样开发产品往回设计。</p>
<p>他们偏好五人小组，偶尔增加到八人。Tobi
认为单人作者能达到一些团队难以达到的高度，AI
也在扩大单人能做的事；但许多项目仍需要合作。他说当时研发团队约三千五百人，实际由许多小组组成，因此更需要前面那种清楚的协调机制。这些规模是他的经验和估计，并非普适最优值。</p>
<p>工作单元要足够私密，又不让办公室死气沉沉。Daniel 做的 pod
放到第七个人就会不舒服，五个人则比较自然，空间本身便在引导小组规模。工作区沿窗，会议室放在中央，避免让每天工作的人待在暗处、把最好日照留给开会。跨层楼梯、咖啡区与团队的位置也经过安排，让基础设施团队去找彼此时，有机会碰到使用那些设施的人。</p>
<p>David 追问，这么强调别照搬，Shopify 自己有没有只学外观？Tobi
当场举出他们所在的多伦多办公室：有些楼层的 pod
太大，好会议室占了临窗位置，原来的机制已经丢失。他们后来重新调整楼层设计。外观像，不代表真正理解了当初为何这样安排。</p>
<p>他尤其受不了让人分不清该推还是该拉的 Norman
door：设计放出的信号，令使用者可预见地做错。很多时候删掉多余把手、改成推板就能修好。门、走廊回声、会议室吸音之所以值得认真做，是因为“产品”只是大量细节组合后的名字；细节组合得好才被整体欣赏，组合不好就是一团混乱。工作环境也在告诉工程师，什么质量可以被接受。</p>
<p>采购又把空间接回了公司的任务。他说办公室用品尽量做到全部来自 Shopify
商家；没有相应产品，就公开寻找愿意创业的人并帮助他们做出来。吸音产品由平台商家一起开发，甚至有一次，为了买中意且价格合适的地板，促成供应商迁到
Shopify，他自己也笑称有点“作弊”。这些案例描述的是在预算与工作需要内找办法，并不能替早期团队的豪华装修辩护。</p>
<a id="21-游戏训练的是反馈不是商业必胜法015837020402"></a>
<a id="21-游戏训练的是反馈不是商业必胜法11836约12340"></a>
<a id="section-21"></a>
<h2 id="starcraft-and-feedback">21. 游戏训练的是反馈，不是商业必胜法 <span class="picks-episode-time">（01:58:37–02:04:02）</span></h2>
<p>StarCraft 给 Tobi
的训练场，是快速反馈与不完全信息。双方开局有相同潜力，但看不到对方每一步。派一个原本能采资源的单位去侦察，就牺牲了眼前产出，换来需要进一步解释的信息。什么时候建基础设施、什么时候补资源、什么时候暴露意图，都不能脱离局势作答。</p>
<p>注意力同样是一种资源。用早期攻击等办法迫使对手同时处理更多事情，可能比直接摧毁基地更有效，因为注意力过载会导致错误。他也喜欢打破熟练对手的预案：有些棋招或打法不在书上，恰恰因为它们并不好，但对一个过度依赖准备的人，反而可能奏效。这里的价值依赖对手与情境，不能抽成“反常规就更好”。</p>
<p>时间不如别人充裕，他便关心怎样从每局获得更多进步。相近水平的匹配和清楚的输赢，使变化容易观察。他同时主动收窄自己的结论：也许只是少年时期恰好遇见了合适的老师，自己也准备好了；其他活动可能教会同样的东西。这是一段个人学习经历，不是游戏会造就好
CEO 的因果证明。</p>
<a id="22-agent-改变了注意力的分配方式020402021144"></a>
<a id="22-agent-改变了注意力的分配方式约1234013144"></a>
<a id="section-22"></a>
<h2 id="agents-and-attention">22. Agent 改变了注意力的分配方式 <span class="picks-episode-time">（02:04:02–02:11:44）</span></h2>
<p>同时运行六个 Agent，再把注意力投向最需要的地方，让 Tobi
想起策略游戏。他描述，Agent
彼此协调，甚至互发邮件；其中一个正做关键模块时，自己就放大那里，做一点干预，再检查持续观察各个
Agent 是否偏离任务的 critic
输出。工作在多处推进，人分配观察、复核与介入的精力。</p>
<p>他特意标明，这个比喻属于 <strong>2026
年第三周</strong>；如果谈话发生在 2025
年最后一周，他可能还不会讲得这么强。支持这种判断的原因也很具体：出现了更能自主运行的
Agent
循环框架，同时有十二月初还不存在、能够达到相应能力的新模型。这里谈的是那一时点的使用体验，不能把六个
Agent 或某种协调形式抽成永久最佳实践。</p>
<p>同样的变化，使公司要求员工遇到问题先尝试 AI
的备忘录，在两人看来越来越像常识。Tobi
预测，两年后别人可能觉得那份备忘录什么也没说；这是他的预测。谈到即将经历的第二十一年，他更在意人准备了什么能力，能多快调整、多快重推旧前提。</p>
<p>这种兴奋没有抹掉创业的偶然性。他回忆，早期多次距离资金耗尽只剩一周，有时靠别人搭救，一些只能闯一次的关几乎擦边通过。他甚至认为，把最初六年重跑一万次，多数可能不会成功；时机、运气，尤其遇见什么人，都很重要。</p>
<p>“如果没有 AI，我可能已经不再经营 Shopify。”（译意）这句话让 David
追问：不是仍然爱这个问题吗？Tobi
区分了使命与职位，稳定时期可能有更合适的领导者，自己也可能改用另一种方式帮助人实现创业。他在
2014
年准备内部演讲时把这一点想清楚：小时候喜欢工程，因为它让自己造东西；后来从代码、产品走到能够造产品的公司，都是把创造和第一笔交易带来的体验分享给更多人。是否继续任
CEO，要看自己还能否作出相应贡献。</p>
<a id="23-哪些东西要写清哪些不能只靠清单021144021831"></a>
<a id="23-哪些东西要写清哪些不能只靠清单1314413831"></a>
<a id="section-23"></a>
<h2 id="measurement-and-judgment">23. 哪些东西要写清，哪些不能只靠清单 <span class="picks-episode-time">（02:11:44–02:18:31）</span></h2>
<p>把招人的判断写成清单，会发生什么？Tobi
担心，公司原先凭品味、经验和对手艺的判断找到团队，随后为了可复制，把这些特质拆成条目。最会研究条目的人便能演出公司想看到的样子，而真正有那些特质的人，未必依赖这份提示。清单记录了表面特征，却可能改变最终被选中的人。</p>
<p>David
接着问，写下来的内容是否也会形成沉没成本，让人不愿公开反悔？Tobi
认同。比起维持前后一致的形象，他更愿意不断吸收较好的信息；即使前面错了，只要还有一次把事情转向较好结果的机会，就应该用。他也承认，整场谈话中可能找得到自己站在相反两边的例子。</p>
<p>他用问题层级解释这些张力。在一个明确的问题空间内，逐步把情况照亮，可能发现自己选错了空间；有时把问题放大，解决更大的问题之后，原来那个局部难题甚至不再需要解决。尺度变了，时间跨度和可用证据也会改变。</p>
<p>数据库性能是否够快，可以跑基准、测量，没必要凭感觉押它未来会变快；决定进入哪个市场，却必须判断
AI
是否会让那个市场消失、被其他产品吸收，以及机器人会怎样改变物流。这类问题要更多依赖趋势与押注。他估计管理者常要穿过四五个层次，把团队眼前的工作接到更大的环境里。</p>
<p>因此，记录决策背景与拒绝把所有品味写成评分表，针对的是不同问题。前者使人有机会理解和修正旧选择，后者警惕把判断替换成可表演的答案。能测量的地方仍应认真测量；无法提前量化的部分，也需要说清它与公司的任务有什么关系。Tobi
的例子很直接：客服处理问题，是在帮助一个人不放弃创业。任务应当能够落到每天做的事情上。</p>
<a id="24-把创业放进更多人的选项021927022323"></a>
<a id="24-把创业放进更多人的选项1392614341"></a>
<a id="section-24"></a>
<h2 id="entrepreneurship-as-an-option">24. 把创业放进更多人的选项 <span class="picks-episode-time">（02:19:27–02:23:23）</span></h2>
<p>一项早年的客户调查，让 Tobi
改变了对创业支持网络的理解。大约高于七成、接近八成的受访客户勾选：如果发出一个创业问题，有人能在
<strong>24 小时内</strong>
回邮件。他最初觉得，有这么多人能得到帮助，实在很好。David
接话提醒，这并不等于一般人群也有这样的资源。</p>
<p>Tobi
说，后来读到幸存者偏差，才意识到方向可能相反：这些人能成为自己的客户，或许正因为有人回答那些问题。他在谈话里进一步把它称作因果关系。不过，本次只有这段调查回忆，没有问卷、原始数据或对照，无法确认支持网络造成创业的效应大小。能保留下来的判断是，已经创业并成为客户的人，不能直接代表所有人。</p>
<p>如果家人和朋友都没有创办过任何东西，创业甚至不会进入一个人的备选项。公开讲述完整经历，让人知道将面对什么，就能把这条路放进更多人的工具箱。Tobi
展望，AI、按需制造、3D
打印和机器人可能使做出东西更容易；人仍需学会发现怎样做出更好的杯子、怎样避免让使用者推拉出错的门。故事缩小信息差，工具帮助人尝试，而他希望
Shopify 能在尝试开始后继续支持这些人。</p><h2 id="原始节目与出处">出处与回听</h2><ul><li><a href="https://www.davidsenra.com/episode/tobi-lutke">David Senra 官方节目页与文稿</a></li><li><a href="https://www.youtube.com/watch?v=ZSM2uFnJ5bs">原始视频</a></li><li><a href="https://shopify.engineering/building-flex-comp">Shopify Engineering：Flex Comp</a></li></ul>
