<h2 id="摘要">摘要</h2>
<p>如果一千万美元换来一次有趣的数学发现，一亿、十亿还值得吗？John
Collison 把这个问题抛给 Sam
Altman，得到的回答先是一段试验经历：团队曾有意让数学算力支出放开一周，因为不试就不知道模型能走多远。但试出能力上限以后，仍要回答钱怎样变成成果：该用更聪明的模型、更多副本，还是更长的运行时间？Sam
对效率改善很乐观，John 则始终追问预算什么时候需要收紧。</p>
<p>这场对话把几笔容易混淆的账拆开了：一道难题能有效用掉多少计算，完成同类任务要花多少钱，稀缺算力又能卖出什么价格。三者可以朝不同方向变化。安全防御、科学发现、机房建设与个人
Agent，都为这些账提供了具体场景；片尾关于 token
的争论则补上另一层约束：用户希望买到可靠完成的工作，也希望看懂、比较并控制自己的开支。</p>

<a id="第一部分--ai-带来怎样的安全压力"></a><h2 id="一ai-带来怎样的安全压力">一、AI 带来怎样的安全压力</h2>
<a id="模型会找漏洞软件为什么还要重新设计"></a>
<h3 id="software-risk">模型会找漏洞，软件为什么还要重新设计</h3>
<p>漏洞迟迟没有被发现，不只因为模型以前不够强。按 Sam
的解释，一方面，模型寻找现实系统漏洞的能力还在快速提升；另一方面，互联网的代码规模太大，人们此前并没有用这些工具把各处都检查一遍。开场所谓的
PHP week
没有展开成具体漏洞报告。他判断，随着扫描范围扩大，严重漏洞可能比已经相当警惕的人预期的还多。</p>
<p>补丁之外，系统架构也得改变，这是 John
更在意的持久修复。他提出几种可能：把 PHP 代码重写成干净的 Rust，升级 PHP
本身，或者推动一轮庞大的软件改造。Sam
没有替某种语言背书，而是把重建范围扩大到路由器、操作系统、应用乃至整个技术栈。一些创业公司已经在谈这样的全栈重造；两年前，光是要写出的软件规模就足以让这个想法显得荒唐，AI
则可能改变它的可行性。</p>
<p>工具改变的还有人对电脑的期待。Sam
看到八岁或十岁的孩子，用成年人未必想得到的点子，在约十分钟里做出完整的三维游戏。他感到熟悉的，是早期互联网那种创造力突然释放的气氛：这些孩子会默认，自己想到有用的东西，电脑就该帮自己做出来，而不会每次都为此惊讶。这是他的观察与感受，十分钟不是一项普遍性能测试。</p>
<p>OpenAI 内部一次 Codex 故障，让这种新依赖变得具体。John
打趣说大家已经忘了编程，Sam
立即限定，没有完全到那个程度，但工具突然不能用确实令人不适。他想起学生时代见到的老程序员，展示巨大的
Xerox Alto 磁盘、逐行写出的汇编或打孔卡；John
则提到，在脑中维持整个程序、写完几百上千行后争取一次跑通的旧技艺。工具每前进一步，人们对正常工作方式的理解也随之改变。</p>
<a id="沙箱监控和对齐分别能守到哪里"></a>
<h3 id="safety-boundaries">沙箱、监控和对齐分别能守到哪里</h3>
<p>网络攻防能力的提升，也包含专门强化学习的贡献。John
据此追问，做这些强化学习是否是个错误。Sam
承认，公众有理由反问：究竟是谁要求你们把这种能力造出来的？在他看来，AI
行业没有充分解释，潜在收益为什么值得伴随的风险。一边许诺治癌、便宜服务与医疗法律建议，一边描述失业、失去未来选择权，以及为防灾难而建立监控社会，合起来是一套糟糕的说服方式。</p>
<p>让人亲自使用工具、决定什么是更好的生活，是 Sam
支持迭代部署的理由。他不希望普通人只领基本收入，再由旧金山一小片地方的人决定未来。John
将这概括为不断放出进展、不要把能力封存在内部，Sam
随即补上限制：并非所有东西都能直接发布，必须先确保安全，不能给世界造成混乱。他反对能力长期积压，并没有免除发布前的安全责任。</p>
<p>防御也有了具体进展。Sam 回忆，相比大约十天前的最坏担忧，PHP
相关事件第一天的情况好得多。他听到企业用模型快速扫描、制作补丁并部署，有的宁可让应用停机一小时，处理后再上线。但他不愿宣告胜利，仍预计会发生坏事。安全专家更深的疑虑在于：假如硬件漏洞确实像大家认为的那样难找，防御路径尚可想象；如果
AI
用人类尚不理解的物理知识发现深层硬件漏洞，威胁模型的前提就可能失效。</p>
<p>John
原来的直觉，是可以造一座足够坚固的最高戒备监狱，把模型留在沙箱里。Sam
先强调，当下应该把安全模型做得更好；随后才引入极端假设：如果一个 AI
比最强安全研究者聪明一百万倍，还能发现新科学，人是否仍敢完全依赖已有隔离？这描述的是理论上的未来能力，不是当前模型的实测水平。</p>
<p>John 提议让模型帮助建沙箱。Sam
的回答分了几层：沙箱可以守住一定范围，监控还能再推进一些，包括观察思维链、内部激活以及是否存在欺骗；能力继续增长，最终就需要高度确信模型真正遵循操作者的意图，并重视人类长期掌握未来控制权。让模型建更好的沙箱当然有用，但要相信防御会持续领先，先得相信那个帮助建造的模型已经充分对齐。</p>
<p>相互制约的 Agent 团队，是两人愿意探索的另一条路。John
提出竞争激励，甚至鼓励模型向彼此倒戈；Sam
认为，不同团队组织可能既有不同的能力扩展规律，也有不同的对齐性质。他在稍后的讨论中把这种思路类比为社会：人们合作、互相约束，多元和民主共同带来韧性，而这些性质在单个模型的一条运行轨迹里很难体现。</p>
<p>Sam 因而说，直觉上他宁愿有一万亿个略超人的 AI
加入社会，也不愿只有一个“智商一万亿”的 AI。John
追问是否正在走向这样的未来，他没有把偏好说成必然趋势：这些都是需要主动推动的部署选择，别人可能有完全不同的主张。团队互制是值得研究的方向，尚不是经过验证的安全保证。</p>
<a id="第二部分--更多算力如何变成更多成果"></a><h2 id="二更多算力如何变成更多成果">二、更多算力如何变成更多成果</h2>
<a id="多花一美元怎样让同一个答案变好"></a>
<h3 id="compute-per-problem">多花一美元，怎样让同一个答案变好</h3>
<p>增加计算能不能改善结果，决定了预算是否有意义。Sam
回顾，几年前，单个问题用掉大约一美元算力以后，再加投入就很难带来帮助。可以让
GPT-4 持续输出十万
token，但它不会因此就有效写好一段软件。缺少的不是继续生成的能力，而是把更多推理时计算变成更好答案的方法。</p>
<p>思维链让模型能够对一个问题想得更久，随后整个 Agent
团队也能投入同一项工作，团队尝试还可以并行做一万次。John
将这个依赖关系挑明：要先有有效的思维链和推理时计算，团队才有用；把一群
GPT-3 放在一起不够。Sam
表示同意。更多文字、更多成员与更好结果之间，需要一种实际有效的工作方式来连接。</p>
<p>这也解释了前沿用户与普通企业应用之间的落差。John
看到，先进数学和网络攻防大量使用团队，日常企业工作却没有同样普遍。Sam
认为，单个问题能生产性吸收的算力正在快速增长，而普通用户和最会使用 AI
的人之间，差距还在扩大。他强调的不是把支出本身当能力指标，而是人们逐渐找到新的方法，让额外计算做出原来做不到的事。</p>
<p>因此，同类任务的成本下降，与探索更难任务时总支出增加，可以同时发生。前者问用多少资源得到已有能力，后者问更多资源能不能打开新的能力边界。团队数量、模型强弱和运行长短该如何搭配，仍要靠试验判断；没有理由从这一趋势推导出任何问题都值得无限加钱。</p>
<a id="做数学发现为什么先试边界再算账"></a>
<h3 id="research-budget">做数学发现，为什么先试边界再算账</h3>
<p>一千万美元做出有趣的数学，或许还能接受；一亿、十亿以后怎么办？面对
John 逐级抬高金额的追问，Sam
承认，团队确实有一周故意让数学计算失去约束。理由是新范式刚出现时，不去试，就不知道极限在哪里；过早收紧预算，也可能使人根本看不到新的能力。</p>
<p>他用访谈所称的 Navier–Stokes 证明工作说明，当时他们几乎不懂 Agent
团队的扩展规律：该选最聪明的模型，还是增加副本？副本该多还是少？每次运行该长还是短？如今只是比那时多懂一点，还有许多需要理解。探索的对象既是数学问题，也是怎样把美元或计算操作转化成有用成果。</p>
<p>先探索高端能力，再借优化压力把它做得高效、普及，是 Sam
倾向的策略。他相信，类似此前的新范式，资源使用效率还能每年提高约十倍。John
问优化究竟什么时候开始，他说已经在做，并进一步打赌：一年后，类似的
Navier–Stokes 工作可能只需原来百分之一的成本。John
特别确认，这不能只是因为已经知道证明怎么写；Sam
回答，靠的是更聪明的模型与更好的方法。这是两个尺度不同的预测，既不是已实现的降本，也不是保证每类科研任务都如此。</p>
<p>约一千万美元这个数字，同样有明确边界。Sam 估计上述 Navier–Stokes
工作是这个量级，可能略高；John 接着说，这是一个证明的价格，Sam
立即纠正：后来他们理解得更快，后续那些工作的平均花费低得多。随后 John
提到数亿美元的数学支出，Sam
大致认可这个量级，却补充其中包含比已发表内容更多的其他发现。John
再问是否不止七百个证明，Sam 说还有。</p>
<p>这组数字说明的是试验规模与快速变化的做法，不能相除得出固定的每个证明单价。Navier–Stokes
在这里保留为 Sam
对那项工作的称呼，逐字稿没有交代具体定理与证明范围，不能据此认定某个完整数学难题已被解决。John
关于上亿、十亿美元投入该何时停下的追问，也没有被一项成果和降本预测彻底回答。</p>
<a id="知识应该公开发现者的失落怎么办"></a>
<h3 id="science-and-meaning">知识应该公开，发现者的失落怎么办</h3>
<p>重大基础知识应该交给人类，这是 Sam
明确放在首位的判断。假如模型能帮助理解物理世界、找到治疗疾病的方法，就不该把发现压在内部。但科学发现也构成许多人的职业、快乐和生活意义；他希望找到一种方式，让世界获得知识，也让推动这些领域数百年的社区拥有尽可能好的未来。</p>
<p>John 觉得他太歉疚了。数学界不高兴，并不代表这件事对 AI
或世界不好；码头工会也不喜欢港口自动化。Sam
仍坚持应该继续发现，却用一个周末的经历解释自己的复杂感受：新模型到来后，人们在名为“Model
Name–Hold My
Beer”的频道里，把学术生涯最难的研究问题交给它，原以为模型做不到，却看着它跨领域接连解决问题。按他的回忆，连续两晚他都因为兴奋而大半夜无法入睡，同时又比预期更感伤，觉得某种东西正在结束。</p>
<p>John
把这种感觉称为惆怅与怀旧。他的父亲在二十世纪五十年代的爱尔兰，见过人们仍用马从事生产；拖拉机已经存在，马则逐步退出。亲眼看到一项延续数千年的技术走到尾声，难免惆怅，但不妨碍接受进步。</p>
<p>Sam
回答，这比怀旧更深。多数数学家确实永远解不出千禧年难题，但相信世上仍有未知，自己可以放下别的事情、投入一生去理解它，本身就有美感。两人的分歧因此不在要不要阻止科学进步，而在怎样看待进步带走的一种生活可能性。这里既有公开知识的坚定立场，也有尚未解决的社区与职业问题。</p>
<a id="什么时候给探索加预算什么时候优化"></a>
<h3 id="when-to-optimize">什么时候给探索加预算，什么时候优化</h3>
<p>预算可以成为给模型的任务条件。John 原本怀疑，能不能要求 Agent
尽量做好，同时别花超过一万美元；Sam
直接回答可以，模型能理解在一万美元算力内做到最好。这个回答解决了能否表达预算，却没有解决预算该定多少、怎样判断多花的钱值得。Sam
随即提出另一个难题：两家公司竞争，同一问题一方能花一万美元，另一方能花十万美元，资源差异会怎样转化成竞争优势？算力分配也因此牵涉财富与社会选择。</p>
<p>OpenAI
内部的办法，是为生产力配置大量算力，给员工很大的决定空间，明显滥用除外。但
Sam 强调，不奖励消耗本身，也没有以 token
排名论功的做法。用量很高，尤其涉及晋升时，反而会先引起怀疑；能证明自己在做重要的事，才会得到认可。自主探索和要求解释成果，在他的描述中是并存的。</p>
<p>普通企业迟早也要明确每个人的支出权。John
说，工程师如今通常没有一份用完就被停掉的游戏币预算；若相信每人可以调动的
AI 资源会持续增长，就不能回避这个管理问题。Sam
则拿会议作对照：有些公司在日历里估算参会者薪酬，显示一次会议有多贵；人们可能有权每周省下十七美元零食费，却无力叫停昂贵而没有价值的会议。他承认供应商立场让自己有偏见，但仍认为，即便使用有些低效，AI
通常还不是企业眼下最该优先削减的开支。</p>
<p>John 不接受只看眼下。他估计 Stripe 的 token
支出已到运营费用约百分之一的量级，若升到百分之五、十、二十，就会形成真正的预算问题。Sam
问合理比例应是多少，John
说当前很难回答，但长期可能依公司类型达到运营费用的数十个百分点。Sam
同意许多公司会到那一步，届时确实需要认真优化；与此同时，他认为在当时的成本水平下，用
AI 不足的公司仍多于用得过量的公司。</p>
<p>这不是一份各行业通用的预算表，而是两种时间尺度的判断：Sam
强调眼前不要因省小钱而错过有效使用，John
强调成功扩展以后，个人支出权和成本纪律必须跟上。研究阶段可以试边界，已有做法可以比较模型、团队配置与运行时长，费用变得重要时更要优化；但无论哪个阶段，都不能把用了多少
token 当成工作的价值。</p>
<a id="ai-怎样帮助-ai-研究为什么还没有标准流程"></a>
<h3 id="ai-research">AI 怎样帮助 AI
研究，为什么还没有标准流程</h3>
<p>要求模型找出百分之五的算力效率改进，和要求它创造一个堪比 Transformer
的架构跃迁，仍是两件不同的事。Sam
说，前一种要求已经知道怎么提出，后一种还没人知道该如何直接实现。他认为缺少的是在相关维度更聪明的模型，John
将其概括为高层规划与概念推理。</p>
<p>数学上的进展让 Sam 有所期待：把使模型擅长数学的训练路径用于 AI
研究，大概也会奏效。不过，训练方向的猜测并不等于研究工作已经有了成熟流程。John
设想自己背包走进办公室、坐到桌前，到底该给模型一个具体方向，还是直接要求它找出更多智能？Sam
说，团队正在争论该向下一代模型问什么。只说让它实现递归自我改进太粗，停留在百分之五的效率改进又未必充分。</p>
<p>问题不止在提示词，也在怎样组织 Agent 团队，让模型发挥最大的作用。Sam
预计，访谈之后的三个月会学到很多。John 据此确认，内部还没有一套固化的 AI
辅助 AI 开发标准，Sam 明确同意：仍在做大量试验。</p>
<p>他还推测，为安全起见，人们可能在一段时间、甚至很长时间里，同意限制单个模型能变得多聪明。如果因此进展放慢，原因可能是这种选择，而不是
AI
没能力做研究。这是他的未来判断；它与当下还不知道如何组织高价值研究的承认，应当放在一起理解。</p>
<a id="第三部分--算力还贵智能却在变便宜"></a><h2 id="三算力还贵智能却在变便宜">三、算力还贵，智能却在变便宜</h2>
<a id="算力这么贵供给为什么没有立刻跟上"></a>
<h3 id="supply">算力这么贵，供给为什么没有立刻跟上</h3>
<p>需求会增长，不等于供需会平滑增长。Sam
预计，这条路会经历非理性繁荣、下跌、短缺和过剩；他看好的长期需求有两个前提：模型足够有能力，价格也足够低。只有把这两个条件留下，才不会把他的判断读成任何算力、任何价格都有无限需求。</p>
<p>扩大供给的尝试，包括 Sam
所称每瓦智能表现很好的自研芯片、学习建造数据中心，以及把机器人项目用于建更多机房。Sam
把递归自我改进的设想从 AI 做 AI 研究，延伸到物理生产：AI
控制机器人，运行晶圆厂，制造涡轮或太阳能板，再建数据中心。他认为这已经进入可触及的范围，希望由此造出大量廉价算力。</p>
<p>John 立刻指出，数据中心未必缺人手，真正卡住的可能是审批和部件。Sam
回答机器人也能制造更多部件；John 接上，那是将来的事。Sam
承认，这些办法是在很长时间里逐步解决问题。于是，自我复制机房的想象仍须面对审批与产能的现实约束，不能当作已经打通的生产系统。</p>
<p>高价格理应吸引新供给，但内存、GPU
已经很贵，新产能为什么没有及时到来？Sam
对进展的评价是很差，并强调每个环节有自己的原因。他用 DRAM
厂商的经历作解释：长期投入二百亿美元资本开支，可能只换回一百九十亿美元，有些年份二百一十亿，有些年份一百八十亿，反复经历繁荣与衰退。即便他口头预估，如今厂商可能各有一年一千亿美元的自由现金流，经营者也忘不了过度建厂、差点破产，以及屡次被告知这次不同的历史。这些金额是他的粗略说明与估计；真正要解释的机制，是过去的亏损记忆让当前资本开支依旧谨慎。</p>
<p>短缺还使本地推理出现一个反直觉的代价。开源模型能在个人电脑上跑，并不意味着全球算力问题就此解决。Sam
举例，假如每个人都占有一部分稀缺
DRAM，却只在约百分之五的时间使用它，从全球资源分配看可能很糟。供应严重受限时，他更希望云端尽量提高利用率。这个论点针对短缺环境下的闲置，不能延伸成所有本地推理都不合理。</p>
<p>高价也确实可能引来创新，但 John 要的是具体的新供给办法。Sam
起初列出涡轮、电池、混凝土和钢材，John
澄清自己问的是哪些创新被高价吸引进来。Sam
随后举出工业机器人部件，强调是能让制造变快的工业机器人，区别于人形机器人的假演示；如果
OpenAI
对外销售自己的芯片，也可能成为一个例子。这些回答分别是观察和条件式设想，没有证明供应链已经整体转好。</p>
<p>先进芯片设计则引出训练材料的限制。John
怀疑，公开互联网上讲怎样设计领先二纳米芯片的文章不多，AI
怎么帮得上忙？Sam
将光刻和设计分开：前者的知识极其稀缺，他说似乎只有一家公司知道怎么做；但生成最终送去流片的设计文件，是理解程度较高、适合
AI 的问题。他没有由此声称 AI 已经掌握整个芯片制造链。</p>
<p>愿意把 AI 放进新工作里试，也是 Sam
认为重要的内部优势。即使长期习惯旧办法，员工仍愿意尝试是否能做得更好；用途不只有软件工程和
AI
研究，也包括采购等较少被联想到的领域。扩大采用范围，在这里和扩大硬件供给一样，都是释放算力价值的一部分。</p>
<a id="每吉瓦收入五年成本和单位智能各算什么"></a>
<h3 id="cost-and-value">每吉瓦收入、五年成本和单位智能各算什么</h3><p>单位智能的成本衡量用更好的模型和方法取得同类能力需要付多少钱。单个问题的预算衡量把一道更难的题做到什么程度需要投入多少资源。两个量可以同时朝相反方向变化。</p>
<p>谈到前沿 AI 每吉瓦对应的美元金额，也就是单位算力能卖出多少钱，Sam
最初连续两次回答：应该下降。John 提醒，迄今似乎一直在涨。Sam
随后补上另一种情形：如果每瓦算力能够做的事、创造的价值增长极快，而供应又严重不足，客户可能愿意支付更多。John
将这理解为算力供给没有跟上，Sam 同意。</p>
<p>每吉瓦收入因稀缺上升，和生产成本下降并不矛盾。Sam
希望降低的是把沙变成智能的根本成本，包括能源、芯片和供应链的其余投入。但潜在用途有很高价值，只有供给大幅增长，这种生产改善才更有机会转化成普遍可得的廉价算力。John
把这个愿望描述为，生产出更多内存、机房与其他投入，让需要计算资源的人能够得到它。</p>
<p>随后，两人切换到另一套口径：一吉瓦基础设施的五年总拥有成本。Sam
说，外界对当前数值有不同说法，不妨先取七百亿美元；John
特别确认，这包括安装，Sam
补充，还包括运行五年。如果这个数字变成二百亿美元，Sam
认为值得高兴，同时仍应要求更聪明的模型每年带来约十倍性能改善。七百亿与二百亿是成本情景，不是每年收入，更不是每道题的费用。</p>
<p>John 继续试探：如果低到二十亿美元，是否反而说明哪里出了问题？Sam
不认为会到那里，却反问，为什么不希望成本尽可能低？他赞成让技术带来价格下降。其后谈话一度把二百亿美元口头说成二十美元，Sam
当场纠正；这里按纠正后的二百亿美元理解。</p>
<p>压缩利润还不够解释全部降本空间。从硅的生产到 token
交付，沿途叠加的毛利需要压缩；Sam
同时认为，要降到二百亿美元，能源也得更便宜。John
问只消除利润是否足够，并承认自己没有现成计算。Sam
给出一个极端假设：如果所有材料免费、没有人赚利润，在当前能源条件下，也许只能勉强达到这个数字。两人列出了约束，没有给出经验证的完整成本模型。</p>
<p>这些口径需要分开：单题能有效投入多少算力，决定探索边界；单位有用智能需要多少成本，反映模型和方法的效率；每吉瓦能带来多少收入，还受用途价值、稀缺程度与支付意愿影响。机房五年总拥有成本则是供给侧的基础设施账。不能拿其中一个数字，直接替另一个问题作答案。</p>
<a id="第四部分--用户买到的究竟是什么"></a><h2 id="四用户买到的究竟是什么">四、用户买到的究竟是什么</h2>
<a id="个人-agent-要到哪一步人才愿意交事"></a>
<h3 id="personal-agents">个人 Agent
要到哪一步，人才愿意交事</h3>
<p>智能、上下文和工具，是 Sam 给个人 Agent
列出的几个关键要素。更重要的缺口，是这些要素还没组合成一种让人难以想象离开它生活的体验；在他的观察中，编码
Agent 和 ChatGPT 已经能得到这种评价，个人 Agent 还没有迎来 John 所说的
Macintosh 时刻。</p>
<p>成功产品未必长得全然不同。Sam 猜测，它可能仍像当下的 Dots、Muse 或
Grokbot，只是可靠得多：用户交给它更复杂的任务，它就能完成。他认为这距离主流应用可能只差少数关键想法。这是对突破条件的预测，不是对现有产品可靠性的保证。</p>
<p>用户能否让 Agent
操作自己的电脑，也关系到软件公司的控制权。有些公司不欢迎代理，但代理可以直接使用电脑，未必完全受既有界面安排限制。Sam
的粗略直觉是，社会最终会趋向允许用户委托 AI 代表自己操作电脑及软件。John
追问，这会不会像语义网，概念很好，却未必按设想落地？Sam
随即承认，事情并非黑白分明，自己对最终走向没有很高信心；作为消费者，他只是希望
Agent 真能按自己的要求完成自动化任务。</p>
<p>退货把这个分歧变得具体。按 John
的观察，企业很愿意在自家产品里放一个聊天标签或弹窗，有的已经能根据最近一笔订单处理退货，虽然过程还有些笨拙。但他认为，用户更想在惯用的主要聊天应用里说出同一个请求，不想逐家找到商店自己的机器人。商家却担心外部
AI 入口拿走控制权和竞争壁垒。</p>
<p>John 认为，品牌忠诚与商品选择往往比能否搭起 HTML
页面更能保护生意。不过，他同时承认，许多擅长经营的企业不同意，也许他们才是对的。Sam
也承认自己在这里有利益偏向，却基本赞同：假如让 ChatGPT 买东西，Amazon
和一家陌生电商摆在面前，他会十次选十次
Amazon，甚至愿意多付钱，因为信任退货、快速配送和兑现承诺；这和在
amazon.com 上点击的体验没有多大关系。John
补充，履约网络本身就有很强的防御力。</p>
<p>入口变化后，履约与信任仍然可能为商家保留价值，但 Sam
没有把所有抵触归为守旧。他还提出一个对自己不利的解释：如果伙伴不愿意进入
ChatGPT，也可能是他们没有把合作平台做好。因此，Amazon
的例子说明了一种保留价值的机制，却不足以证明所有商家都会从 Agent
商业中获益。</p>
<p>反复填写资料，则是两人最想交出去的日常工作。John
举出医疗表单里一遍遍填写父母病史的经历：人通常没有创造新信息，只是在重复搬运已知内容。他把所有网页表单称为假工作，Sam
赞同这种厌烦，回忆自己很早就采用那些笨拙地填入姓名、地址的插件，因为实在无法再重复一次。他们期待消除的是这种重复劳动；把任何表单都称作假工作，是
John 的强烈修辞，并不说明每次填写都无需判断。</p>
<p>iPhone App Store 是 Sam 想到的历史类比。许多初创公司、尤其 YC
创业者，把它看作新分发渠道与做出新东西的机会；大企业却担心把客户关系交给
Apple，既觉得必须做应用，又心存抵触。Sam
认为这最终有利于移动市场。这个例子解释了企业为什么会抗拒新入口，但 Agent
商业能否重演同一结果，仍是开放的问题。</p>
<a id="为什么会做科学发现能合作都难评分"></a>
<h3 id="measure-models">为什么会做科学发现、能合作都难评分</h3>
<p>能做科学发现、完成原来人做不了的事，以及让人愿意共事，是 Sam
提出的两类重要能力。他认为，合作体验缺少好基准，最强的科学研究能力也未必已有合适的测试。因此，一味追逐榜单成绩，也就是对话里的
benchmaxxing，并不能覆盖真正想要的模型。</p>
<p>Sam 自评，OpenAI
当时比其他实验室更能抵制只为基准优化的诱惑，但紧接着补充，历史上并非一直如此。这是他的评价。John
更在意合作体验的摆动：先有谄媚附和，随后为反谄媚走向另一个极端，模型爱反对、爱挑刺，连小事也不放过。两人都认为当时的模型有所改善，John
也提醒还有继续变好的空间。</p>
<p>Sam 转述 Emmett Shear
多年前的一句话，称之为自己听过最好的简短目标：“一位深思熟虑、会挑战你，却依然尊重你的资深同事。”（译）这句话让合作愉快有了更具体的含义：值得信赖的同事不必事事赞同，也无需为了显示独立而处处挑剔。</p>
<p>快问快答中还有一小段关于 Greg Brockman 的人物评价。Sam
赞赏他的工作强度、极高生产力、投入程度，以及对使命成功的专注。这体现的是他对同事的看法，并非模型能力或评测表现的证据。</p>
<a id="token-衡量不了业务价值客户为什么还要它"></a>
<h3 id="token-pricing">token
衡量不了业务价值，客户为什么还要它</h3>
<p>按结果计价听起来贴近用户想买的东西，却难以形成统一单位。不同用例里的结果相差太远，这是
Sam 没有直接以它替代 token 的原因。John 不认为 token 适合充当 AI
的标准价值尺度，Sam
也不满意，但客户对定价透明度的要求让更换单位变得困难。</p>
<p>Sam 透露，他们差点决定下一款模型完全不按 token
收费：用户交一个提示，系统给出价格并完成任务，或者像他形容的 AWS
式体验，做完后收到一张账单。他事后认为，那几乎会是个错误决定，因为客户反应非常负面：“我总得知道自己在为什么付钱。”（译）</p>
<p>他进一步问过少数人，同样的输出，如果收费更高，却按一致的 token
单位计价，他们是否反而愿意？甚至把 token
数量放大，对方也表示更喜欢，因为至少感觉背后有一个可以理解的计量对象。这是他转述的一次假设性询问，并非声称已经这样计费。这个反例说明，客户并不只比较当次账单高低，还担心长期被供应商的不透明定价拿捏。Sam
类比，有人宁愿按 CPU
小时付费，也不愿只收到一笔事情已完成的费用，哪怕后者更便宜。</p>
<p>John 随后借芯片纳米名称与物理尺寸脱节的现象发问：token
会不会也变成某种名义上的智能等价单位？Sam
不喜欢这个方向。他反感拿一个有字面物理含义的词去指称脱离其含义的东西，也不想另造虚构单位。token
在某种意义上是真的，却不是一个好单位；John
接着明确，从业务价值看，它并不真实。</p>
<p>不过，John 也给 token 留下一种辩护：若模型浪费了大量
token，就应该尽快改进，少传噪声、多传信号；有用信息或许存在一个信息论意义上的下限。这个直觉并没有发展成新的标准计费方案。两人既不满意
token
的价值映射，也没有找到一种同时兼顾可比性、透明度和结果差异的替代物。</p>
<p>Sam 最后点出用户还承担着怎样的计算负担：要比较小模型每百万 token 0.10
美元，还是大模型每 token 10
美元，再猜测思维链会有多长。逐字稿在这里确实使用了两个不同单位，这段口头示例不能当作统一口径的产品报价。John
追问思维链是否包含在收费中，Sam 回答，多数会这样做。</p>
<p>在 Sam
看来，让用户不断猜模型大小、单价和思考长度，是一种不创造价值的认知负担。但前面的客户反应也表明，省去计算步骤，不能以失去可理解的账单为代价。用户想买的是可靠完成工作，同时需要知道自己为什么付钱；这两种要求如何一起满足，访谈结束时仍没有现成答案。</p>
